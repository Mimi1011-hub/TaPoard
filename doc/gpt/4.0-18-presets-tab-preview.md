# 4.0-18 プリセットのタブ・サイズ選び・スマホ比率のプレビュー

作業の決まりは `doc/gpt/4.0-00-working-rules.md` のとおり（外部パッケージ禁止、C# 5、1行160文字以内、JS 1ファイル300行以内、画面の文字は日本語・英語とも辞書に入れる。機械翻訳は使わない）。
ブランチ: `develop/4.0` から `gpt/4.0-18-presets-tab-preview` を切る。
コミットの作者は「TaPoard Developer」と GitHub の noreply アドレス。Co-Authored-By などの行は入れない。

設定ウィンドウ（`web/v4/settings.html` と `web/v4/settings/`）の使い勝手を、Hiro のプレビュー版の感想に沿って直す。4つの部分からなる。

## 0. 先に直す不具合: 2文字のアイコンがはみ出す

「ミュート切替」（Discord、アイコンは `chat` = `●●`）を置くと、青い四角から白丸2つがはみ出して壊れて見える。ボタンの上でも、詳細欄の「アイコンを変える」の横でも同じ。

原因: 絵（`presetPaths`）を持たない 72 個のアイコンは文字（グリフ）で描いている。3.1 にあった次の2つが v4 に移っていない。
- 2文字以上のグリフ（`chat` `●●`、`users` `♟♟`、`copy` `▣▣`、`previous` `◀|`、`next` `|▶` など）を `span.glyph-wide` で包んで小さくする処理
  （3.1 の `web/app.js` 653 行付近。`git show develop/3.1:web/app.js` で見られる）。v4 の `presetIconNode()` は `textContent` に入れるだけ。
- `.preset-icon` の `white-space: nowrap; overflow: hidden; line-height: 1;` と、`.preset-icon .glyph-wide { font-size: 0.62em; letter-spacing: -0.05em; }`
  （`git show develop/3.1:web/style.css` の `.preset-icon`）。v4 の `deck.css` には `.glyph-wide { font-size: 0.75em; }` だけがあり、使われていない。

直し方:
- `web/v4/deck/icons.js` の `presetIconNode()` で、2文字以上のグリフは `span.glyph-wide` に入れる（`innerHTML` は使わず要素を作る）。
- グリフが必ずアイコンの四角の中に収まるようにする（折り返さない・はみ出さない）。ボタンの大きさ 1×1 ～ 大きいボタン、アイコンの大きさ 40% ～ 100% で確かめる。
- 3.1 と見比べて、アイコンの四角の角の丸み・文字の太さなど、移し忘れた見た目がほかにあれば合わせる（色は v4 の「アイコンの色」のままでよい）。
- 同じ描画を使う所すべてで確かめる: スマホ画面、PC ウィンドウ、設定のプレビュー、詳細欄、アイコン選びの一覧、プリセットの説明。
- UI テスト: 2文字グリフのアイコン（`chat`、`previous`、`copy`）で、文字の幅と高さがアイコンの四角の中に収まっていること。

## 0-2. 先に直す不具合: 「起動・その他」の部品が置いて1秒で消える

カタログの「起動・その他」にある「URL を開く」「文字をコピー」「音の出力先」「音の入力元」を置くと、約1秒で消える（カスタムキーだけは残る）。
指示書17で直したのは別の経路で、実機の原因はこちら。

原因: `catalog-items.js` の `catalogItem()` はこれらを中身が空のまま作る（`url: ''`、`text: ''`、`deviceId: null`）。
PC は保存のとき `ActionSteps.ValidateEntryAction` で空の URL・空の文字・選ばれていない音声機器を断る（400）。
`saver.js` は 400 を受けると `restoreSaved()` で最後に保存できた状態へ戻すので、置いた部品が消える。そのとき履歴も空になる。

直し方:
- これらを置くときは、先に必要な中身を聞く小さな入力欄を出す（既存の `confirm-dialog.js` と同じ作りの自前のダイアログ。ブラウザーの `prompt` は使わない）。
  - URL を開く: URL（`http://` か `https://` で始まること。PC と同じ検査を画面側でも行い、だめなら理由を出して閉じない）。
  - 文字をコピー: コピーする文字（空は不可、長さの上限は PC と同じ）。
  - 音の出力先・入力元: PC の機器の一覧（`GET /api/devices`。`details/audio-device-details.js` と同じ）から選ぶ。1つも無いときはその旨を出して置かない。
  - 「置く」で初めて配置する。「やめる」なら何も置かない（履歴にも残さない）。ドラッグで置いたときは、落とした枠を覚えておき、入力が済んだらその枠に置く。
- 詳細欄で URL や文字を空にしたときも同じことが起きる。空・不正の間は保存に出さず、欄の下に理由を出す（部品は消さない）。
- それでも PC に断られたとき（400）は、左下の保存の表示だけでなく、画面上の通知（`onNotice` / `showNotice` と同じ見せ方）で
  「保存できなかったので元に戻しました：{理由}」と出す。黙って消えるのをやめる。
- UI テスト: 4つの部品それぞれを入力して置く → 保存の POST に中身が入っている → 消えない。「やめる」で何も置かれない。
  テスト用の偽の PC も、空の URL・文字・機器には 400 を返すようにして、本物と同じ動きで確かめる。
- C# テスト: 空の URL・空の文字・機器なしの保存が 400 になること（今の動きの確認）。

## 0-3. 先に直す不具合: 「起動・その他」で「戻る」が効かない

カタログの「起動・その他」に入ると、上の「戻る」を押しても最初の一覧へ戻れない。

原因: `catalog.js` の `render()` は部品一覧の「戻る」に `() => this.openTop(this.top)` を渡している。
「起動・その他」は `flat: true`（グループを挟まない）なので、`openTop()` がまた同じ部品一覧を開いてしまう。Esc キーで呼ばれる `back()` は正しく動く。

直し方: 「戻る」ボタンも `this.back()` を呼ぶ。UI テスト: 「起動・その他」に入り「戻る」を押すと最初のカードの一覧に戻ること。

## 1. プリセットを独立したタブにする

今は「保存」の中にプリセットがあり、場所として違和感がある。

- 左のナビに「プリセット」を追加する。並びは 配置 / プリセット / 見た目 / 保存 / 接続 / PC / 全般。
- 「保存」からプリセットを外す。「保存」はルックとバックアップだけになる（`saved.js`）。
- `&section=presets` でも開けるようにする（ほかの section と同じ扱い）。

### 1-1. プリセットのプレビュー

プリセットを押すと、右のプレビュー欄が「そのプリセットの見本」に切り替わる。

- 今プリセットのカード内にある小さな図（`presets.js` の `map()`）はやめ、プレビュー欄に実際のボタンと同じ見た目で出す
  （`preview.js` と同じ描画を使う。見本は読み取り専用で、選択・ドラッグ・削除はできない）。
- 見本を出している間、プレビュー欄の見出しは「プリセットのプレビュー：{name}」にし、その隣に「戻る」ボタンを置く。
  「戻る」で自分の画面のプレビューに戻る。
- 見本の間は、ページの切り替え・枠数・「元に戻す」・右の詳細欄は使えなくする（隠すか無効にする）。向き（横・縦）の切り替えは使え、見本もその向きに変わる。
- ほかのタブへ移ったとき、プリセットを使ったとき、も自分の画面のプレビューに戻る。
- 「このページに使う」は今までどおり、戻ったあとに表示されるページ（押す前に見ていた向き・ページ）へ上書きする。確認の文も今のまま。
- 「ボタンの説明」（送るキーの一覧）はプリセットのタブ側に残す。

### 1-2. 自分のプリセットを追加できるようにする

- プリセットのタブに「今のページをプリセットに追加」ボタンを置く。名前を聞いて（`promptFn`）、プレビューに出している向き・ページを保存する。
- 保存する中身: その向きの枠数、そのページのボタンとウィジェット（位置・大きさ・アイコン・文字など）、そのページのフェーダー配置。
- 保存先は PC の `data\presets.json`（設定ファイルとは別）。最大 30 個。名前は 40 文字まで。
- 一覧は「用意されたプリセット」と「自分のプリセット」に分けて出す。自分のプリセットには「名前を変える」「削除」を付ける（削除は確認あり）。
- 自分のプリセットは保存した向きの分しか持たない。反対の向きを見ているときは「このプリセットは{side}用です」と出し、「このページに使う」は押せなくする。
- 使うときの検査は用意されたプリセットと同じ（枠数が変わるときの確認、ほかのページの並べ直し、PC 側の「元に戻す」）。
- アプリを開くボタンなど PC に依存するものも、そのまま保存してよい（同じ PC で使う前提。書き出し・読み込みは今回やらない）。
- API（管理者のみ。`LookController` / `PageController` の今のプリセット API に合わせる）:
  - `GET /api/presets`: 今の一覧に自分のプリセットを足して返す（`custom: true` と、持っている向きが分かる形）。
  - `POST /api/presets/save` `{ name, orientation, page }`、`POST /api/presets/rename` `{ id, name }`、`POST /api/presets/delete` `{ id }`。
  - `POST /api/presets/apply` は自分のプリセットの id も受ける。
- 壊れた `presets.json` は無視して、用意されたプリセットだけを出す（起動を止めない）。

## 2. カタログでサイズを選べるようにする

今はデジタル時計などを置いたあと、詳細欄で大きさを変える。置く前に選べるようにする。

- カタログで、大きさを複数持つ部品（`widgetDefinitions` に複数のサイズがあるもの。時計、天気、PC 情報、スライドショー、テンキー、タッチパッドなど）を押すと、
  そのすぐ下に「2×1」「2×2」のようなサイズのボタンが並ぶ。もう一度押すと閉じる。
- サイズのボタンを押す（またはドラッグする）と、その大きさで置く動作になる。置き方は今のカタログと同じ。
- 向きの枠数に入らないサイズは押せない状態で出す。
- サイズが1つしかないもの（ふつうのボタン）は今までどおり1回で置ける。
- カタログの検索結果・「最近使った」でも同じ動きにする。

## 3. プレビューをスマホの比率で見られるようにする

今のプレビューは枠が正方形になる比率（列数：行数）で出るが、スマホでは画面いっぱいに広がるので横長（縦向きなら縦長）に見える。

- プレビュー欄の道具の並びに「見え方」の選択を足す: 「PC ウィンドウ」「スマートフォン」。
- 「PC ウィンドウ」は今のまま（列数：行数）。
- 「スマートフォン」はスマホの画面の比率で出す。比率は次の順で決める。
  1. 自動: 最後につないだスマホの画面の大きさ。スマホ側の画面（`web/v4` のビューア）が、表示領域の幅と高さを PC に送る
     （既存の状態取得や接続時の通信に載せる。新しい通信を増やすなら 1 回だけ、向きが変わったときにもう 1 回）。
     PC は端末ごとに覚える（`PairedDevice` に幅・高さを足す。個人が分かる情報は足さない）。
  2. 手で選ぶ: 「自動 / 16:9 / 18:9 / 19.5:9 / 20:9 / 4:3（タブレット）」の一覧。まだ1台もつないでいないときの自動は 19.5:9 とする。
- 縦向きのプレビューでは比率を逆（9:19.5 など）にする。
- 選んだ見え方と比率は PC ウィンドウの設定としてこの PC に覚える（スマホの表示には影響しない）。
- スマートフォン表示のとき、枠が正方形でなくなっても、ドラッグで置く位置の計算・背景の位置合わせ・選択枠がずれないこと。
- プリセットのプレビュー（1-1）も同じ見え方で出す。

## 4. 幅がせまいときの文字切れ

- 設定ウィンドウの幅 1100px と 1280px で、全タブの文章・ボタンが切れたり1文字ずつ折り返したりしないこと。
  長い文は折り返し、長い名前は省略記号（…）と `title` で見せる。
- プリセットのタブを含め、日本語・英語の両方で確認する。
- 接続タブの「スマートフォン / 古いスマートフォン」の切り替え（`connect-qr.js`）は、今「古いスマートフォ / ン」と折り返して見た目が悪い。
  2つのボタンを欄の幅いっぱいに同じ幅で並べ、文字は1行に収める（`white-space: nowrap`）。
  幅が足りないときは文字を途中で折らず、ボタンを縦に2段に積む。その下の説明文も欄の幅で折り返し、右端で切れないこと。
  幅 1100px の日本語・英語で、ボタンの高さが2つとも同じであることを UI テストで確かめる。

## 5. テスト

- C#: 自分のプリセットの保存・名前変更・削除・使う（枠数が変わる場合を含む）、30 個の上限、壊れた `presets.json`、端末の画面サイズの保存。
- UI（Playwright、`tests/v4-settings-*.cjs`）:
  - プリセットのタブ: 押すとプレビューが見本になる、「戻る」で戻る、見本の間は編集できない、使うと元のページに入る、自分のプリセットの追加・名前変更・削除。
  - 「保存」にプリセットが無いこと。
  - カタログ: サイズのボタンが出る、選んだ大きさで置ける、入らないサイズは押せない。
  - プレビュー: 見え方を切り替えると比率が変わる、スマートフォン表示でドラッグして狙った枠に置ける。
  - 幅 1100px で文字切れが無いこと（日本語・英語）。
- 既存のテストをすべて通す（`tests/run-unit.ps1`、`node tests/*.mjs`、`tests/v4-*-ui.cjs`）。
