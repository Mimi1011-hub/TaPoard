# 4.0-24 プリセットの書き出し・読み込みと、AI のアイコン案内に見本の画像

作業の決まりは `doc/gpt/4.0-00-working-rules.md` のとおり（外部パッケージ禁止、C# 5、1行160文字以内、JS 1ファイル300行以内、画面の文字は日本語・英語とも辞書に入れる。機械翻訳は使わない）。
ブランチ: `develop/4.0` から `gpt/4.0-24-preset-files` を切る。
コミットの作者は「TaPoard Developer」と GitHub の noreply アドレス。Co-Authored-By などの行は入れない。
項目ごとにコミットする。上から順に行う。
UI テストの偽の PC は、本物と同じ形を返し、本物と同じものを断ること（指示書 20 の決まりのまま）。

Hiro の希望:
- 「今のページをプリセットに追加」と「プリセットを読み込む」を付ける。
- 「保存」タブの「保存した画面」に書き出しを付け、それをプリセットとして読み込めるようにする。
- AI でアイコンを作る案内に「作りたい絵の見本の画像を添えて頼む」を足す。

今の作り: 自分のプリセットは `data\presets.json`（`src/CustomPresets.cs`、最大 30 個）。1つのプリセットは「1つの向きの1ページ」
（`orientation`、`columns`、`rows`、`speaker`、`mic`、`items`）。保存した画面は `data\icon-styles\`（`src/IconStyles.cs`）で、
`deck` に両方の向きの全ページが入っている。

## 1. プリセットのファイルの形を決める

- 拡張子は `.tppreset`。中身は UTF-8 の JSON:
  `{ "format": "tapoard-preset", "version": 1, "presets": [ { "name", "orientation", "columns", "rows", "speaker", "mic", "items" }, ... ] }`
  （`id` は入れない。読み込むときに新しく付ける。）
- 1つのファイルに何個入っていてもよい（上限 40 個。それより多いファイルは断る）。大きさは 2MB まで。
- PC 側（C#）に、書き出し（`CustomPreset` の一覧 → ファイルの中身）と、読み込み（ファイルの中身 → 検査 → `CustomPreset`）を作る。
  読み込みの検査は `ValidateStored` の決まりに加え、**ボタン1つずつを `POST /api/v3/deck` の保存と同じ検査に通す**
  （部品の大きさ・種類は `WidgetRegistry`、位置が枠の中で重ならない、アクションの値、アイコンなど）。1つでも通らないプリセットは読み込まない。
- **ほかの人からもらったファイルを読み込むことがあるので、安全のため次を守る:**
  - アプリを起動する・URL を開く・文字を入力するボタン（`path` `args` `url` `text` や手順 `steps` を持つもの）があるときは、
    読み込む前の確認に「アプリを起動するボタン 2 個、URL を開くボタン 1 個が入っています。中身を確かめてから使ってください。」のように種類と数を出す。
    起動するアプリのパスは確認の中に一覧で出す（長いものは省略してよいが、ファイル名は必ず見えること）。
  - 自分で選んだ画像のアイコン（`customIcon`）と、この PC に無いアイコンパックのアイコン（`iconPack` / `iconPackItem`）は持ち込まない。
    標準のアイコン（`iconKey`）に戻す。書き出すときも `customIcon` は入れない。
  - 音の出力・入力先（`deviceId` `deviceTarget` `deviceName`）は PC ごとに違うので、書き出すときに外す。読み込んだボタンは「既定の装置」のまま。
- テスト（C#）: 書き出して読み込むと同じプリセットになる。壊れたファイル、`format` 違い、40 個より多い、2MB より大きい、
  枠からはみ出す部品、許されない大きさの部品、`customIcon` 入りを、それぞれ正しく断る・外す。
  起動するボタンの数と種類を数える処理のテスト。

## 2. プリセットタブ: 読み込む・書き出す・今のページを追加

- タブの上の方に、ボタンを2つ並べる: 「今のページをプリセットに追加」（今もある）と「プリセットを読み込む」（`.tppreset` を選ぶ）。
  どちらも 1100px の日本語・英語で1行に収まること。入らなければ縦に並べる。
- 「自分のプリセット」の各行に「書き出す」を足す（今の「名前を変える」「削除」と並べる）。そのプリセット1つの `.tppreset` を保存する。
  ファイル名はプリセットの名前（ファイル名に使えない文字は `_` にする）。
- 読み込むとき:
  - ファイルに入っているプリセットの一覧（名前・横向き/縦向き・枠数・ボタンの数）をチェックボックス付きで出す。最初は全部にチェック。
  - 1 の安全の確認（起動するボタンなど）をこの一覧の下に出す。
  - 「読み込む」を押すと、チェックしたものを「自分のプリセット」に足す。同じ名前があれば「名前 (2)」のようにする。
  - 30 個の上限を超えるときは、足せる数を出して、それより多くはチェックできないようにする。
  - 読み込んだら一覧を出し直し、最初に足したものを選んでプレビューに出す。
- 「今のページをプリセットに追加」は、ページの「⋮」メニューと「ページ一覧」にも「プリセットに追加」として置く（そのページを追加する）。
- API は今の `/api/presets/...` に揃える（例: `POST /api/presets/import` に読み込んだファイルの中身と選んだ番号、`POST /api/presets/export` に id の一覧）。
  `ApiRouteTableTests` に足す。どちらも管理者（設定ウィンドウ）だけ。

## 3. 保存タブ: 保存した画面を書き出す

- 「保存した画面」の各行に「書き出す」を足す（今の「この画面に戻す」「名前を変える」「削除」と並べる）。
- 書き出すと、その画面の**両方の向きの全ページ**を1ページ 1 プリセットとして入れた `.tppreset` を保存する。
  名前は「保存した画面の名前 横 1」「… 縦 2」のようにする（英: "<name> Landscape 1"）。中身が空のページは入れない。
  フェーダーはそのページで見えている置き場所（今の `Effective` と同じ）。
- 背景は入れない（プリセットはボタンの配置だけ、という今の決まりのまま）。書き出すときの説明に一言書く:
  「ボタンの配置をプリセットのファイルにします。背景は入りません。」
- 書き出したファイルは、2 の「プリセットを読み込む」でそのまま読み込める（どのページを読み込むかは、読み込むときの一覧で選ぶ）。
- テスト: C# で、保存した画面（3.1 の古い形 `deck` が `Settings` のものを含む）から書き出せる。UI で、書き出し → 読み込み → 一覧でページを選ぶ → 自分のプリセットに入る。

## 4. AI でアイコンを作る案内に、見本の画像を添える

`web/v4/settings/icon-ai-guide.js` の案内の 2 番（頼む文）を次のようにする。

- 頼む文の前に、一文を足す:
  「作りたい絵の見本（好きなアイコンの画像や、手描きのラフなど）があれば、一緒に添えて頼むと、思った絵柄に近づきます。」
  （英: "If you have a sample of the look you want, such as an icon you like or a rough sketch, attach it to your request. The results will be closer to what you have in mind."）
- 頼む文を2つにする（どちらもコピーのボタン付き）:
  - 見本なし: 今の文のまま。
  - 見本あり: 「添付した画像と同じ絵柄・色合いで、正方形 512×512 の PNG、背景は透明のアプリのアイコンを作ってください。作るもの: …」
    （英: "Using the same style and colors as the attached image, make square 512×512 PNG app icons with a transparent background. Icons to make: …"）
- 5 番の注意に一文足す: 「見本に使う画像も、人が作ったものは使ってよいか確かめてください。」
  （英: "If the sample is someone else's work, check that you are allowed to use it."）
- 案内の文はクロが確かめるので、上の文から変えるときは自然な文にすること。
- UI テスト: 2つの頼む文があり、それぞれコピーできる。1100px の日本語・英語で切れない。
