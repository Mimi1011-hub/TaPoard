## 3. やること

### 3.1 C# の辞書の仕組み

新しいファイル：`src\Text.cs`、`src\TextJa.cs`、`src\TextEn.cs`。

- `TextJa.cs`・`TextEn.cs`：それぞれ `static class` に `internal static readonly Dictionary<string, string> Values` を1つ持つだけ。1行に1項目。キーは `tray.openSettings` のように「場所.意味」。
- `Text.cs`：

```csharp
static class Text
{
    internal static string Language { get; }            // "ja" か "en"（今使っている言語）
    internal static string Preference { get; }          // "auto"・"ja"・"en"
    internal static void Use(string preference);        // 切り替える。"auto" は Windows の表示言語（ja で始まれば ja、ほかは en）
    internal static string Get(string key);             // 今の言語 → 無ければ英語 → 無ければキーそのもの
    internal static string Get(string key, params object[] values);   // String.Format と同じ {0} {1}
    internal static event Action Changed;               // 切り替わったとき
}
```

- 言語を足すときは `TextXx.cs` を1つ足して `Text.cs` の表に1行足すだけ、という作りにする。
- スレッドをまたいで読まれるので、言語の切り替えは参照の入れ替えだけにする（読み取り側で lock しなくてよい形）。
- 設定の保存：`data\language.txt` に `auto`・`ja`・`en` のどれか1語（無ければ `auto`）。起動のいちばん最初（トレイを作る前）に読む。`settings-v3.json` には入れない。
- 新しい `tests\TextTests.cs`：日本語と英語のキーがぴったり同じ、英語の値に日本語の文字が無い、`{0}` などの数が両方で同じ、`Use("en")`・`Use("ja")`・`Use("auto")` の切り替え、無いキーはキーが返る。`tests\run-unit.ps1` の一覧に足す。

### 3.2 `src\` の日本語をすべて辞書に移す

`src\*.cs` の文字列の中にある日本語（約 500 か所）を `Text.Get(...)` に置きかえます。多い順の目安：`DeckPresets.cs`（181）、`InputSessions.cs`、`WidgetRegistry.cs`、`DeckV3Validator.cs`、`AppImporter.cs`、`ShortcutPacks.cs`、`PcWindow.cs`、`InputController.cs`、`DeckController.cs`、`DeckLayoutV2.cs`、`WeatherService.cs`、`IconPacks.cs`、`ShortcutKeys.cs`、`SettingsFile.cs`、`AudioDevices.cs`、ほか約 25 ファイル。まず `grep` で一覧を出してから、ファイルのまとまりごとに進める。

- 文をつないで作っている所（`"スライドショーは" + n + "枚まで"` など）は、1つの文にして `{0}` を使う（英語は語順が違うため）。
- **`static readonly` の欄や定数に日本語が入っている所**（プリセットの表など）は、起動時の言語で固まってしまう。言語を切り替えたあとも正しく出るように、**使うときに `Text.Get` を呼ぶ形**（メソッドやプロパティ）に直す。`DeckPresets` はここが中心。プリセットの名前・説明・ボタン名はすべてキーにする。
- 例外の文（API の `error` として画面に出るもの）も同じく辞書に移す。出るのは PC の言語。
- 初期設定で作るボタンやページの名前（`SettingsFile.cs` など）も辞書から。**もう保存されている名前は書きかえない**（新しく作るときだけ）。
- トレイのメニュー（`Program.cs`）、PC 用ウィンドウの右クリックメニューと確認（`PcWindow.cs`）、WebView2 が無いときの案内（`WebView2Host.cs`）、アプリの追加の窓（`AppImporter.cs`）、設定ウインドウの題名（`SettingsWindow.cs`）、ファイアウォールの文（`FirewallCheck.cs`）を含む。
- **もう出ている窓やメニューは `Text.Changed` で作り直す**：トレイのメニューは作り直す。PC 用ウィンドウのメニューは次に開くときに新しい言語になっていればよい。
- コメントは今のまま（英語）。ログに出すだけの文はそのままでよい。
- 新しい `tests\SourceTextTests.cs`：`src\*.cs`（`TextJa.cs` を除く）を読み、**文字列の中に日本語の文字が1つも無い**ことを確かめる（コメントは見ない。`//` から行末と `/* */` を外してから調べる）。`tests\run-unit.ps1` に足す。
- 今ある C# テストで日本語の文を比べているものは、テストの最初で `Text.Use("ja")` を呼ぶ。

### 3.3 言語を切り替える API と「全般」の欄

- API（`SystemController.cs`、どちらも `ApiAccess.Admin`）：

| API | 内容 |
|---|---|
| `GET /api/v3/language` | `{ preference: "auto", language: "ja", languages: [{ id: "ja", name: "日本語" }, { id: "en", name: "English" }] }` |
| `POST /api/v3/language` | `{ preference }`（`auto`・`ja`・`en` だけ。ほかは 400）→ GET と同じ形 |

- `POST` は `data\language.txt` を書き、`Text.Use` を呼ぶ。`tests\ApiRouteTableTests.cs` の表を更新する。
- `GET /api/v3/state` に `pcLanguage`（今の PC の言語）を足す。**スマホはこれを使わない**（スマホは今までどおり、スマホ自身の設定とブラウザの言語）。
- 設定ウインドウと PC 用ウィンドウ（`?view=pc`）は **PC の言語に合わせる**：開いたときと、`pcLanguage` が変わったときに `i18n.setLanguage` を呼ぶ。ブラウザの言語や `localStorage` の `tapoard-lang` はこの2つの画面では見ない。
- 「全般」（`settings\general.js`。長くなるなら `settings\language-setting.js` に分ける）に「言語」の選択（自動（Windows に合わせる）／日本語／English）を足す。選ぶと `POST` して、設定ウインドウの文字がその場で変わる。言語の名前はその言語のまま出す（英語の画面でも `日本語` と出す）。
- CSS を付ける（13 の「全般」の項目と同じ見た目）。

### 3.4 Web 側の取りこぼし

- `web\v4\` の `.js`・`.html` に残っている日本語をなくす。分かっているもの：`input\sender.js` の `BUSY_MESSAGE`、区切りの `・`・`、`・`：`・`（` `）`（`shell.js`・`catalog.js`・`icon-packs.js`・`weather-place.js`・`presets.js`・`widgets\wheel.js` など）。区切りは辞書の文に入れる（例：`"packs.countAuthor": "{count}個・{author}"`、英語は `"{count} icons · {author}"`）。
- 残してよいもの：`i18n\ja.json`、`settings\icon-words.js`（アイコンを探すための日本語の言葉）、記号だけの文字（`▦`・`✓`・`×`・`›` など）。
- `en.json` の見直し：日本語が残っている値を直す（`menu.languageJa` は言語の名前なので `日本語` のままでよい）。直訳で意味が通らないものを直す。**キーは変えない。**
- `tests\i18n-test.mjs` に足す：`en.json` の値に日本語が無い（言語の名前のキーだけ許す）、`{count}` などの差し込みが両方の言語で同じ。
- 新しい `tests\web-text-test.mjs`：`web\v4\` の `.js`・`.html`（上の「残してよいもの」を除く）の文字列と HTML の文に、ひらがな・カタカナ・漢字が無いことを確かめる（コメントは見ない）。

### 3.5 インストーラー

`installer\Installer.cs` は別の exe なので、`src\Text.cs` は使えません。

- `Installer.cs` の中に同じ考え方の小さな表を持つ（日本語と英語、キーで引く）。1ファイルが長くなるなら `installer\InstallerText.cs` に分け、`package.ps1` のコンパイルの行に足す。
- 言語は Windows の表示言語で決める（ja で始まれば日本語、ほかは英語）。切り替えの欄は作らない。
- 画面の文、ボタン、確認、エラー、ファイアウォールの説明のページ、最後の案内をすべて。**日本語の文は変えない。**
- `packaging\setup-lan.ps1`・`remove-firewall.ps1`・`setup-helper.ps1`・`初回セットアップ.cmd` が出す文も、Windows の表示言語で日本語と英語を出し分ける（PowerShell は `(Get-UICulture).Name`）。ファイル名は変えない。
- `packaging\README.txt` は日本語のまま残し、同じ内容の英語を `packaging\README.en.txt` に足す。`package.ps1` のコピーと確認の一覧に足す。
- インストーラーの文にもテストを足す（`tests\InstallerTextTests.cs`：キーが同じ、英語に日本語が無い）。今ある `InstallerCopyTests` の動かし方に合わせる。

### 3.6 言語を切り替えたときの確かめ

- 新しい `tests\v4-settings-language-ui.cjs`（`v4-settings-connect-ui.cjs` と同じ作り）：
