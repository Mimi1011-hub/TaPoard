## 1. 不具合: 設定ウィンドウを小さくすると、プレビューの上の帯が2行になり、重なる

設定ウィンドウを一番小さく（`SettingsWindow.cs` の `MinimumSize` 1100×640）すると、

- 「横向き」「縦向き」「元に戻す」のボタンの文字が2行に折り返す（「横向 / き」）。
- 画面比率の一覧（`#settings-preview-ratio`）が「16:9（iPhone 8・iPhone SE 第2/第3世代 など）」と長いので帯からはみ出し、右の詳細欄（`#settings-inspector`）の上に重なる。
- 2段目（ページのタブ・枠数・おすすめの枠数）もはみ出し、おすすめの枠数が詳細欄の文字と重なる。

直し方:
- プレビューの上の帯のボタン（向き・元に戻す・戻る）は `white-space: nowrap` にし、折り返さない。
- 画面比率の一覧の文字は比率だけにする（「自動（390×844）」「16:9」「18:9」「19.5:9」「20:9」「4:3」。英語も同じ）。機種の例は下の 2 で右の欄に出す。
- おすすめの枠数を2段目から外す（下の 2 で右の欄へ移す）。
- 帯と2段目の中身は、プレビューの列（`.settings-preview-column`）の幅を超えないこと。入りきらないときは見出し「画面のプレビュー」を先に省略（…）し、それでも足りなければページのタブの列を狭めて横スクロールにする（今のタブの作りのまま）。
- UI テスト: 幅 1100px・高さ 640px で、日本語と英語の両方、見え方を「PC」と「スマートフォン」の両方で、
  帯と2段目のボタン・一覧がすべて1行（高さが1行分）で、どれもプレビューの列の右端を超えず、詳細欄と重ならないこと。

## 2. 画面比率の案内とおすすめの枠数を、右の詳細欄に出す

Hiro の案: おすすめの枠数を2段目に入れると狭くなるので、比率を変えたときは右の詳細欄（ボタンを選んだときに設定が出る欄）を「画面比率の案内」に変える。機種の例もそこに出す。

- 詳細欄に「画面比率の案内」を出すのは次のとき:
  - 見え方を「スマートフォン」に変えたとき、画面比率を変えたとき、向き（横・縦）を変えたとき。ボタンを選んで設定を出している最中でも、案内に切り替える。
  - 見え方が「スマートフォン」で、何も選んでいないとき（今の「ボタンを選ぶと…」の文の代わり）。
  - ボタンやフェーダーを選ぶと、今までどおりその設定に戻る。見え方が「PC」のときは今までどおり。
- 案内の中身（日本語・英語。機種名は英語のまま）:
  - 見出し「スマホの画面比率」（英: Phone screen ratio）と、今の比率と向き（例「19.5:9・横向き」）。
  - 機種の例。指示書 21 の文をそのまま使う。
    - 自動: 「最後につないだスマホ（幅×高さ）」。まだつないだことが無いときは「まだスマホをつないでいません。19.5:9 として表示します」（今の自動の扱い `phone-grid-advice.js` / `preview.js` と同じ）。
    - 16:9: iPhone 8・iPhone SE 第2/第3世代 など
    - 18:9: Pixel 3 など少し前の Android
    - 19.5:9: iPhone X 以降・Galaxy S シリーズ など
    - 20:9: Pixel 7 以降・多くの Android
    - 4:3: iPad
  - 「おすすめの枠数」の見出しと、指示書 21 の `recommendedGrids()` の結果のボタン（「列 7 × 行 4」のように列と行が分かる書き方）。
    今の枠数と同じものは「今の枠数」と分かる見た目にして押せなくする。押すとその向きの枠数を変える（今の枠数の変更と同じ確認・元に戻すが効く。下の 3 の知らせも同じに出る）。
  - 今の枠数でマスが横長・縦長になるときは、その知らせ（`settings.preview.wideCells` / `tallCells`）もここに出す。プレビューの下の知らせは今のまま残す。
- `settings-app.js` は 300 行に近いので、案内の画面は新しいファイル（例: `web/v4/settings/phone-ratio-panel.js`）に作る。`preview-view.js` の `renderPhoneAdvice` から2段目の `#settings-grid-advice` を使う部分を外す。
- UI テスト:
  - 見え方を「スマートフォン」にすると詳細欄に案内が出て、機種の例とおすすめの枠数のボタンがある。
  - ボタンを選んで設定が出ている状態で比率を変えると、案内に切り替わる。もう一度ボタンを選ぶと設定に戻る。
  - おすすめの枠数を押すと枠数が変わり、「元に戻す」で戻る。今の枠数のボタンは押せない。
  - 幅 1100px の日本語・英語で、案内の文字が詳細欄からはみ出さない（折り返すのはよい）。

## 3. 枠数を変えて入らないときは、どのページかを知らせる

今は、枠数を小さくしてフェーダーが入らないとき「フェーダーまたは部品が新しい枠に収まりません」とだけ出る（`grid-size.js` の `settings.grid.cannotFit`）。
ボタンが入らないときの確認も「{count} 個のボタンが入りません。」だけで、どのページか分からない。

直し方:
- `deck-rules.js` の `reflowOrientation()` が、入らない部品とフェーダーのあるページの番号（1 から）を返すようにする（例: `{ count, pages: [1, 2], faderPages: [3] }`）。
- フェーダーが入らないとき（今の `error`）:
  「ページ 1・2 がはみ出します。フェーダーが新しい枠に入りません。フェーダーを小さくするか削除してから、枠数を変えてください。」
  （英: "Pages 1, 2 would overflow. A fader does not fit in the new grid. Make the fader smaller or delete it, then change the grid."。ページが1つなら "Page 1 would overflow."）
- ボタンが入らないときの確認:
  「ページ 1・2 がはみ出します（{count} 個のボタンが入りません）。空いている所へ並べ直しますか？」
  （英: "Pages 1, 2 would overflow ({count} buttons do not fit). Rearrange them into available spaces?"）
- ページに名前があるときは「ページ 1（配信）」のように名前も添える。ページが多いときは5つまで書き、残りは「ほか 3 ページ」とする。
- 枠数の一覧とおすすめの枠数のボタン（どちらも `GridSize.set()` を通る）で同じ知らせを出す。プリセットの枠数の変更（`presets.confirmGrid`）は PC 側で並べ直すので今のままでよい。
- 知らせのあと、枠数の一覧は元の値に戻る（今の動きのまま）。
- テスト:
  - node のテストで、`reflowOrientation()` が返すページ番号（ボタンだけ・フェーダーだけ・両方・名前つき・6ページ以上）。
  - UI テストで、2ページ目に 4×2 のフェーダーを置き、列を 3 にすると、「ページ 2」の入った知らせが出て、枠数が元に戻る。
  - UI テストで、1・2ページ目の右端にボタンを置き、列を減らすと、確認の文に「ページ 1・2」が入る。
