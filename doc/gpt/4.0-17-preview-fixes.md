中身（テストはまだ回していない。下の各項目の「確認」を必ず行うこと）:

- 音量フェーダー: スピーカーを動かすとマイクが 0 になる（逆も同じ）。
  原因は PC の `/api/audio` が動かした側の値だけを返し、`fader.js` の `apply()` がそれで `audio` 全体を上書きしていたこと。

- テンキー 4×5 の左上 Num を「C（クリア）」に変更。`numpad-clear` は PC で Esc（0x1B）を送る。拡張キー扱いは外した。辞書に `keypad.clear`（クリア / Clear）を追加。テストの `numpad-numlock` も置き換え済み。

## 1. カスタムキーが消える不具合（未修正・要調査）

手順: カスタムキーを置く → 削除する → 別のキーを置く → 約1秒で消える → その後「戻る」を押しても何も起きない。

クロの見立て（未確認）:
- 1秒で消えるのは `saver.js` の保存（600ms 後）が 400 を受け、`editor.restoreSaved()` で最後に保存できた状態に戻しているため。
- 400 の理由をまず突き止める。`DeckV3Validator` / `DeckController` のどの検査で落ちているかを、C# テスト（`DeckV3SaveTests` と同じ形）で
  「key-custom を追加して保存 → 削除して保存 → 別のキーを追加して保存」と再現して確認する。
  削除した項目の id が残る・新しい項目に古い id が付く（`copyGeneratedIds` は type と位置だけで照合している）なども疑う。
- 「戻る」が効かないのは、履歴が拒否された配置を再現して再び 400 → 元に戻る、を繰り返しているためと思われる。
  400 のあとに履歴をどう扱うか（拒否された状態を履歴から外す等）も直す。
- 400 のとき画面に出るエラー文が利用者に分かる内容か確認する。

## 2. 接続画面の表記

- タブ名を「スマートフォン」「古いスマートフォン」（英: Phone / Older phone）にし、辞書に入れる（今は文字が直書き）。
- 各タブの下に短い説明を付ける。例: 「ふつうはこちら」「スマートフォンでつながらないときはこちら（IP アドレスで開きます）」。
- 内部の値（`iphoneUrl` / `androidUrl`）の名前は変えなくてよい。
