## 3. やること

### 3.1 入力の送り役

部品から PC へ入力を送る共通の仕組みです。3つの部品はこれを使うだけにします。

- `InputSessions`（`sessions.js`）：部品 id ごとの入力セッション（`sessionId`・`nextSequence`）を持つ。
  - `/api/v3/state` の応答と `/api/view` の応答に入っている `inputSessions` で入れ替える。**すでに持っている同じ `sessionId` の `nextSequence` の方が大きければ、そちらを残す**（今の `applyInputSessions` と同じ。送信中の応答で番号が戻らないように）。
  - 07 の `Store` に `inputSessions` が入るので、`Store` の更新を受けて入れ替える形でよい。
- `InputSender`（`sender.js`）：部品 id ごとに1つ。今の `inputSender` と同じ動き：
  - `steps(n)`・`move(dx, dy)`・`wheel(delta)`・`button(type, control)`・`keyTap(control)`・`keepalive()`・`release()`・`listen(fn)`。
  - 送る前に同じ種類をまとめる（`steps`・`wheel` は足す、`move` は足す、0 になったら捨てる）。
  - 1回に最大16件。`steps` は1件 ±20 まで、`move` は ±4096 まで（超えた分は次へ）。
  - 前の送信から 50ms 空ける。前の送信が返るまで次を送らない。
  - `POST /api/input` `{ viewId, sessionId, sequence, events }`。返ってきた `acknowledged + 1` を `nextSequence` に。`foregroundBlocked` なら `listen` へ `'blocked'`、それ以外は `'ok'`。
  - タイムアウトは1回だけやり直す。サーバーの `error` が「他の端末が操作中です。」なら `'busy'`。それ以外の失敗はそのセッションを捨てて表示を知らせ直し（3.2）、`'error'`。
  - セッションが無いときは送らずに捨て、表示を知らせ直す。
  - `release()`：送るものが無くなったら `POST /api/input/release` `{ viewId, sessionId }`。`keepalive()`：送信中でなく待ちも無いときだけ `POST /api/input/keepalive`。
  - 部品が作り直されても送り役は同じ id のものを使い続ける（`listen` は新しい部品で上書き）。
- 「他端末が操作中」「管理者権限の画面には操作できません」の表示（`showInputNotice`）は、3つの部品で共通の小さな関数にする（busy は2秒、blocked は3秒で消える）。

### 3.2 表示中の部品の知らせ方を直す

08 では `visibleIds` が「部品表にある type」になっていますが、今の画面と同じにしてください。

- 知らせる部品は今の `visibleWidgetIds` と同じ type：`metrics`・`weather`・`wheel`・`touchpad`・`keypad`（最大40個）。`clock` と `slideshow` は入れない。
- この type の一覧は `widgets\registry.js` に「PC に知らせる部品」として持たせ、`phone-app.js` に直接書かない。
- `ViewAnnouncer` は `/api/view` の応答の `inputSessions` を `InputSessions` に渡す。
- 入力の送り役が「知らせ直して」と言ったら、前回と同じ並びでも送り直す（今の `announcedViewSignature = ''` と同じ）。

### 3.3 ホイール

- 縦型（指を上下になぞる）と回転型（円をなぞる）。`options`（`style`・`sensitivity`・`multiplier`・`reverse`・`ctrl`・`shift`・`alt`・`middleClick`）の範囲と初期値は今の `wheelOptions` と同じ。
- しきい値・1段の距離・速さで段数が増える計算・軽くたたいたら中クリック（`middleClick` のとき）・指を離したら `release()`・押している間 `keepalive()` は、今の `bindWheelGesture`・`bindRotaryGesture` と同じ。
- 1段ごとの手応え（`wheelFeedback`）は 08 の `Feedback` を使う。
- 下の説明（`Ctrl+Shift + ホイール ×2` など）は言語ファイルから作る。
- サイズ 1×1・1×2・2×2 の見た目は今と同じ。

### 3.4 タッチパッド

- 1本指で動かす、たたいて左クリック、2本指でたたいて右クリック、2本指でスクロール、たたいてすぐなぞるとドラッグ（押している間 `keepalive()`）、長押し。今の `bindTouchpadGesture` と同じしきい値と送り方。
- `options`（感度など）は今の `touchpadOptions` と同じ。
- 3×2・2×3 の見た目と、操作中・busy・blocked の表示は今と同じ。

### 3.5 テンキー

- 4×4 と 4×5 の並び（4×5 は PC のテンキーと同じ形で `NumLock` あり）、送るキー名（`numpad-7` など）は今の `keypadTile` と同じ。押したら `keyTap(キー)` → `release()`。
- キーを押した見た目と手応え。

### 3.6 PC ウインドウ

PC ウインドウ（C# の `PcWindow`、WebView2）が開く画面を新しい画面にします。C# 側と話す決まり（下の表）は**今と1文字も変えない**でください。

- C#：`src\Program.PcWindow.cs` の `DeckUrl` を `"/?view=pc#connect=…"` から **`"/v4/?view=pc#connect=…"`** にする（この1か所だけ）。
- 新しい画面は、URL に `view=pc` があるか、`sessionStorage` の `tapoard-pc-window` が `'1'` なら PC ウインドウとして動く（今と同じ。`#connect=` を消したあとも `?view=pc` は残す）。
- `web\v4\pc\` に分ける（例：`pc-host.js` で C# とのやり取り、`pc-pointer.js` でウインドウの移動・大きさ変更、`pc-info.js` で情報表示）。スマホ用の `PhoneApp` に `if (pc)` を散らさず、PC ウインドウのときは PC 用のクラスが足りない所を足す形にする。

C# との決まり（今の `setupPcWindow` と同じ）：

| 向き | 内容 |
|---|---|
| C# → 画面 | `window.tapoardPc.set({ info, aspect, viewOnly, resizable, barVisible })`、`page(-1 / 1)`、`menu()`、`rebase()` |
| 画面 → C# | `chrome.webview.postMessage` で `raise`、`page:<n>/<m>`、`drag:<0〜1の横位置>`、`resize:<辺>`、`move:<dx>,<dy>`（物理ピクセル）、`dragend` |

- `set`：`info` なら右下に「描画 fps / PC との往復 ms（2秒ごとに `/api/ping`）/ 最後の操作 ms / 接続中」を出す。`aspect === 'fill'` なら枠いっぱい、それ以外は列×行の形を保って黒い帯（今の `body.pc-window` の CSS と同じ）。`viewOnly` なら「見るだけモード　Ctrl+Alt+V で戻す」。
- ページが変わるたび `page:<n>/<m>` を送る（ページ名は 10 で足すので、今は数字だけ）。
- ボタン・部品以外の所を押すと：辺の近く（10px、`resizable` のとき。上辺は `barVisible` でないときだけ）なら `resize:`、それ以外は `drag:`。スワイプがオンなら、素早く横にはらったときだけページ送り、それ以外はウインドウの移動。動かしている間 `move:`、離したら `dragend`。押したら必ず `raise`。辺の上ではカーソルを矢印に。
- マウスホイール：ボタンの上ではページ送り（今と同じ溜め方）。ホイール部品の上では1目盛り1段（`bindPcWheelSteps`）。タッチパッドの上ではスクロールを送る。Ctrl+ホイール（拡大）は止める。
- タッチパッドの上の右クリックは、そのまま右クリックとして送る。右クリックのメニューは出さない。
- PC ウインドウでは：上の帯（`TopBar`）を出さない（C# 側の帯にページとメニューがある）。画面の維持・振動/クリック音は使わない。メニューは「スワイプでページ送り」と「言語」だけ（接続を切る・画面を維持・振動は出さない）。
- 操作の往復時間（`/api/action` と `/api/input`）を「最後の操作」に入れる。

### 3.7 テスト

- `tests\v4-input-ui.cjs`（08 と同じ偽サーバー・`locale: 'ja-JP'`・wakeLock の差し替え）：
  - ホイール（縦）を上へなぞると `/api/input` に `steps` が正しい向きで届き、`sequence` が `acknowledged + 1` で増えていく。離すと `/api/input/release`。
  - 回転型で円をなぞると `steps` が届く。`middleClick` で軽くたたくと中クリック。
  - タッチパッド：動かす（`move`）、たたく（左クリック）、2本指でたたく（右クリック。Playwright の `touchscreen` か CDP の `Input.dispatchTouchEvent` を使う）、2本指スクロール（`wheel`）。
  - テンキー 4×5 で `numpad-numlock`・`numpad-enter` が届く。
  - 偽サーバーが「他の端末が操作中です。」を返すと「他端末が操作中」が出て2秒で消える。`foregroundBlocked: true` なら管理者権限の表示。
  - 送信中に届いた古い `inputSessions`（小さい `nextSequence`）で番号が戻らない。
  - 入力の部品があるページで `/api/view` に id が入り、`clock` の id は入らない。
- `tests\v4-pc-window-ui.cjs`：
  - `/v4/?view=pc#connect=test` で開くと上の帯が無く、`window.tapoardPc` がある。
  - `chrome.webview.postMessage` を偽物に差し替えて（`addInitScript`）、空いた所を押して動かすと `raise`・`drag:`・`move:`・`dragend` が順に届く。`set({ resizable: true })` のあと右下の角で `resize:bottomright`。
  - ページを変えると `page:2/3` などが届く。`tapoardPc.page(1)` でページが進む。
  - `set({ info: true })` で情報表示が出る。`set({ viewOnly: true })` で見るだけモードの表示。`set({ aspect: 'fill' })` で枠いっぱい。
  - ボタンの上でホイールを回すとページが変わる。ホイール部品の上では `steps` が送られる。
  - メニューに「接続を切る」「画面を維持」が無い。
- 07・08 のテスト（`v4-phone-ui.cjs`・`v4-widgets-ui.cjs`・`i18n-test.mjs`）も通ること。
