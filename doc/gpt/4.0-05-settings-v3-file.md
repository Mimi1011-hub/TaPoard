# 依頼書 4.0-05：設定ファイルを v3（settings-v3.json）にする

TaPoard 4.0 作り直しの段階4（前半）です。設定ファイルを、世代ごとの項目が混ざった `settings-v2.json` から、**「向き → ページ → 部品」の形に整理した `settings-v3.json`** に切り替えます。v2 のファイルは**読むだけで書き換えず**残すので、3.1 と 4.0 を同じ PC で行き来しても 3.1 の設定は壊れません。

今回は**ファイルの形と変換だけ**を変えます。アプリの中（Controller や DeckLayoutV2）は今までどおり v2 の `Settings` クラスで動き、読み込むときに v3 → v2、保存するときに v2 → v3 に変換します。中の処理を v3 で直接動かす（Service 化）のは次の依頼書 06 です。

## 2. v3 の形

`data\settings-v3.json`。プロパティ名はこのとおりにする（ファイルの形式になるため）。

```json
{
  "schemaVersion": 3,
  "security": {
    "token": "…48文字…",
    "pairingKey": "…12文字…",
    "devices": [ { …PairedDevice のまま… } ]
  },
  "deck": {
    "keepAwake": true,
    "background": { …DeckBackground のまま… },
    "landscape": {
      "columns": 5,
      "rows": 3,
      "faders": {
        "speaker": { "row": 0, "column": 4, "width": 1, "height": 2, "off": false },
        "mic":     { "row": 2, "column": 4, "width": 1, "height": 1, "off": false }
      },
      "pages": [
        {
          "faders": null,
          "items": [
            { "id": "…", "type": "app", "name": "…", "row": 0, "column": 0, "width": 1, "height": 1, …ボタンの項目… }
          ]
        },
        {
          "faders": { "speaker": { "row": 1, "column": 0, "width": 3, "height": 1 }, "mic": null, "speakerHidden": false, "micHidden": true },
          "items": []
        }
      ]
    },
    "portrait": { …landscape と同じ形… }
  },
  "weather": { "name": "…", "latitude": 0, "longitude": 0, "timezone": "…" },
  "pcWindow": { …PcWindowOptions のまま… }
}
```

決まり：

- **ページは配列の順番がページ番号**（0 から）。空のページも `{ "faders": null, "items": [] }` として入れる。ページ数は `DeckLayout.Pages(s, 向き)` と同じ数。
- **部品（items）は、そのページに置かれたボタン・部品**。v2 の `AppEntry` から `orientation`、`landscape`、`portrait`、`size`、`width`、`height` を除いた項目をそのまま持ち、位置と大きさは `row`、`column`、`width`、`height`（どれも 1 以上の実際の値。`DeckLayout.Width/Height` で求めた値）で持つ。並び順は v2 の `apps` の順番を保つ。
- **faders**（向きごと）：v2 の `landscapeSpeaker` / `landscapeMic`（`ControlPlacement`）と `landscapeSpeakerOff` / `landscapeMicOff` を入れる。
- **pages[i].faders**：v2 の `landscapeControlPages` に `page == i` の項目があるときだけ入れ、ないときは `null`（＝向きの共通の位置を使う）。`speaker` / `mic` は `ControlPlacement`（なければ `null`）、`speakerHidden` / `micHidden` はそのまま。
- v2 の古い世代の項目（`columns`、`rows`、`speakerSlot`、`micSlot`、`speakerSize`、`micSize`、`landscapeSpeakerSlot` などの Slot / Size 系、`pageCount`、`landscapePageCount`、`portraitPageCount`）は **v3 に入れない**。v3 → v2 に戻すときに今の `DeckLayout` の関数で作り直す。
- 天気は `weatherName` / `weatherLatitude` / `weatherLongitude` / `weatherTimezone` を `weather` にまとめる。

## 3. やること

### 3.1 v3 のクラス（`src\SettingsV3.cs`）

上の JSON に合うクラスを作る：`SettingsV3`、`SecurityV3`、`DeckV3`、`OrientationV3`、`FadersV3`、`FaderV3`（ControlPlacement の項目＋`off`）、`PageV3`、`PageFadersV3`、`DeckItem`（AppEntry から位置関係を除いて `row`/`column`/`width`/`height` を足したもの）、`WeatherV3`。`PairedDevice`、`DeckBackground`、`PcWindowOptions`、`ControlPlacement`、`TilePosition` は今のクラスをそのまま使う。

### 3.2 変換（`src\SettingsMigration.cs`）

```csharp
static class SettingsMigration
{
    // v2 → v3。s は読み込み時の正規化（Program.LoadSettings と同じ DeckLayout.Migrate / Validate 済み）を前提とする。
    internal static SettingsV3 ToV3(Settings s);
    // v3 → v2。今の Controller や DeckLayoutV2 がそのまま使える Settings を作る（古い世代の項目も DeckLayout で埋める）。
    internal static Settings ToV2(SettingsV3 v3);
}
```

- **往復で変わらないこと**：正規化済みの v2 設定 `s` について、`ToV2(ToV3(s))` を JSON にしたものが、`s` を同じ手順で正規化して JSON にしたものと一致すること（テストで確かめる。比べる前に両方へ同じ正規化をかけてよい）。
- `ToV2` の後、`DeckLayout.Validate` が通ること。
- ページ数より後ろのページを指す `ControlPages` の項目は v3 に入れない（このとき往復の比較では、比べる前に同じ項目を取り除いてよい）。
- `ToV3` は入力の `s` を書き換えない（コピーして使う）。
- `ToV2` で作る `AppEntry` の `size` は、`DeckLayout.Migrate` と同じ決まり（`width == height && width <= 2 ? width : 1`）で埋める。web は `size` も見ているため。

### 3.3 ファイルの読み書き（`src\SettingsFile.cs` を書き換える）

- `CurrentSchemaVersion = 3`、`FileName = "settings-v3.json"`。v2 のファイル名は `V2FileName = "settings-v2.json"` として残す。
- **読み込みの順番**：
  1. `settings-v3.json` があれば読む。読めない・`schemaVersion` が 3 でない・3 より新しいときは、今の v2 と同じように**例外を出して止める**（v2 へ勝手に戻らない。メッセージのファイル名は v3 にする）。
  2. なければ `settings-v2.json` を読み、v2 として返す（呼ぶ側が今までどおり正規化する）。**このとき v2 のファイルは書き換えない。** 次の保存で v3 ができる。
  3. どちらもなければ `createDefaults()`。
- **1.x の `settings.json` からの移行はやめる**（4.0 で古い互換を削る決定のため）。`LegacyFileName` と、その読み込み・テストを消す。
- `Load` が返すのは今までどおり v2 の `Settings`（v3 を読んだときは `SettingsMigration.ToV2` した結果）。`Save(Settings)` は `ToV3` してから `settings-v3.json` に書く（今と同じく一時ファイル → 置き換え）。
- `Settings.schemaVersion` はメモリ上は 2 のまま扱ってよい（ファイルに書くのは `SettingsV3.schemaVersion = 3`）。

### 3.4 自動バックアップ（`src\SettingsBackups.cs`）

- v3 のバックアップは **`data\backups-v3\`** に置く（v2 の `data\backups\` は触らない・一覧にも出さない）。件数（30件）と間隔（2分に1回まで）は今と同じ。
- `Read` は v3 のバックアップを読んで `ToV2` した `Settings` を返す（復元の処理は今のまま動く）。

### 3.5 テスト

`tests\run-unit.ps1` に足す。実際の `data\` には書かず、テストごとに一時フォルダーを使う。

- `tests\SettingsV3Tests.cs`（新規）：
  - 横・縦それぞれにボタン・2×2 の部品・ページごとのフェーダー上書き・「すべてのページから削除」・空のページ・背景・天気・PC ウインドウ設定・端末を含む v2 設定を作り、**往復（ToV2(ToV3(s))）で一致**する
  - `ToV3` の結果で、ページ数・各ページの部品数・部品の row/column/width/height・pages[i].faders の有無が期待どおり
  - v3 の JSON に `orientation`、`landscape`、`portrait`、`speakerSlot`、`landscapePageCount` などの古い項目が**出てこない**
  - フォルダーに v2 だけ → `Load` が v2 の中身を返す → `Save` で `settings-v3.json` ができる → **v2 のファイルのバイト列が変わっていない**
  - v3 と v2 の両方 → v3 を読む
  - v3 が壊れている／`schemaVersion` が 4 → 例外で、v2 にも v3 にも書き込まない
  - `Save` を2回 → `backups-v3\` にバックアップができ、`backups\` は増えない
- `tests\SettingsV2Tests.cs`：1.x の `settings.json` の移行に関するテストを消し、残りは v3 のファイル名に合わせて直す（v2 → v3 の読み込みとして意味が通るように）。
- 既存の `ApiStatusTests`・`ControllerTests`・`Release103Tests` などが通ること。
- `test.ps1`：3行目で `dist\data\settings-v2.json` から接続キーを読んでいるので、`settings-v3.json` の `security.token` を読むように直す。98〜99行目の「data のファイルが配信されないこと」に `/data/settings-v3.json` も足す。
