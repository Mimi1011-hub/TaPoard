## 1. 必ず守ること

- **最初に `doc\gpt\4.0-00-working-rules.md`（`4.0案\00_作業の決まり.md`）を読んで守る。**

- **1ファイル 300 行まで。** 役割ごとに `class`。グローバル変数を作らない。`editor-state.js` は今ちょうど 300 行なので、足すときは先に中身の一部（例：フェーダーの処理）を別ファイルに分けて行数を空ける。

- **C# は変えない。API も増やさない。** 古い画面（`/`・`/settings`）も変えない。
- スマホ用の部品（`core\`・`deck\`・`widgets\`）は作り直さない。足りない所は小さな export や引数を足すだけ（スマホの動きは変えない）。

## 2. 使う API（すべて既存・管理者キー）

| 用途 | API |
|---|---|
| ボタンの変更（アイコン・色・一括変更） | 今までどおり `EditorState` を変えて `Saver` が `POST /api/v3/deck` |
| 背景 | `POST /api/background`（背景の全部を JSON で）、`POST /api/background/image` `{data,width,height}`、`POST /api/background/image/delete`、`GET /api/background/image` → 返り値の `background` |
| アイコンパック | `GET /api/icon-packs`（`packs, maxPacks, maxIcons`）、`GET /api/icon-packs/get?id=`、`POST /api/icon-packs/create` `{name,author}`、`/add` `{id,icons}`、`/rename` `{id,name,author}`、`/delete` `{id}` |
| プリセット | `GET /api/presets`、`POST /api/presets/apply` `{id,orientation,page}` |
| 見た目の保存 | `GET /api/icon-styles`（`styles, maxStyles`）、`POST /api/icon-styles/save` `{name}`、`/apply` `{id}`、`/rename` `{id,name}`、`/delete` `{id}` |
| バックアップ | `GET /api/backups`、`POST /api/backups/restore` `{id}` |
| サーバー側の「元に戻す」 | `POST /api/page/undo`（プリセット・見た目・バックアップを使った直後に1回だけ） |

背景はデッキの保存（`/api/v3/deck`）とは別です。サーバーは v3 の保存で背景を上書きしません。

#### 3.5 背景

手本：`app.js` の `backgroundColors`・`backgroundGradients`（5183〜5205 行）、`renderBackgroundControls`・`useBackgroundImage`・画像を外す・位置の調整（5206〜5760 行あたり）。

- 色（並び）・2色のグラデーション（並び）・好きな色（`input type=color`、2色目のオン・オフ）・画像を選ぶ・画像を外す・合わせ方（`fit`）・拡大・暗くする（`dim`）・ぼかし（`blur`）・ボタンの見え方（`keys`：自動 / 透ける / 標準）・ボタンの透け（`keyClear`）・初めに戻す。
- 変えたら `POST /api/background` に背景の全部を送る（スライダーは 300ms 待ってから）。返ってきた `background` をプレビューに反映する。**背景はデッキの保存（`Saver`）や `History` に入れない。** `EditorState` に `setBackground(background)`（`dirty` にしない、`source: 'background'` で知らせる）を足して、プレビューはそれで描き直す。
- 画像：30MB まで。長い辺 2560px までの JPEG にして、185 万文字以下になるまで小さくする（今と同じ）。送ったら位置の調整を始める。
- 位置の調整：「プレビューで位置を調整」を押すと、**プレビューの上でドラッグで移動・ホイールで拡大**。横と縦で別々（プレビューの向きの切り替えに合わせる）。「完了」で保存。調整中はボタンを動かせない。処理は `settings\background-adjust.js` に。
- 背景がほかの所で変わったとき（同期で `background` が変わる）は、プレビューと欄を描き直す。

### B（チャット2）

#### 3.6 サーバー側で設定を変える操作の流れ

プリセット・見た目を使う・バックアップから戻すは、サーバーが設定をまとめて書き換えます。どれも同じ流れにして、`settings\server-change.js` に1つだけ書く：

1. まだ保存していない変更があれば、先に保存し終わるのを待つ（`Saver` に `flush()` を足す。失敗・409 ならそこで止める）。
2. 確認（何が上書きされるかを書く）。上書きされる前に「今の見た目を保存しますか」と聞く（`askSaveLook`、5114 行〜。上限に達していれば保存できない理由を出す）。
3. API を呼ぶ。
4. `/api/v3/deck` を読み直して、`History` を空にする（11 の `reloadDeck`）。
5. 「元に戻す」付きのお知らせを出す。押すと `POST /api/page/undo` → 読み直し。ほかの変更をした後は、サーバーのエラー文をそのまま出す。

#### 3.8 見た目の保存・バックアップ
