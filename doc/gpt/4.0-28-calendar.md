作業の決まりは `doc/gpt/4.0-00-working-rules.md` のとおり（外部パッケージ禁止、C# 5、1行160文字以内、JS 1ファイル300行以内、画面の文字は日本語・英語とも辞書に入れる。機械翻訳は使わない）。
ブランチ: その時点の `develop/4.0` から `gpt/4.0-28-calendar` を切る（指示書 27 とは別のブランチ。27 の後でも前でもよい）。
コミットの作者は「TaPoard Developer」と GitHub の noreply アドレス。Co-Authored-By などの行は入れない。
UI テストの偽の PC は、本物と同じ形を返し、本物と同じものを断ること（指示書 20 の決まりのまま）。

Hiro の希望: 予定は入れない。普通に日付を表示するだけのカレンダー。Google などとの同期も無し。

## 1. 大きさと見た目

`WidgetRegistry` に `calendar`（「カレンダー」/ "Calendar"）を足す。大きさで表示が決まる（表示の種類を選ぶオプションは無い）。

- **1×1（今日）:** 今日の日付（大きな数字）と曜日（日本語「火」、英語 "Tue"）。上に小さく月（「11月」/ "Nov"）。
- **2×1（週）:** 今週の7日を横に並べる。各日に曜日（小さく）と日付。**今日の日付に丸**（強調の色 `--color-accent` の丸、数字は濃い色）。
  上か左に小さく月を出す（週が月をまたぐときは「11月–12月」/ "Nov–Dec"）。
- **3×3（月）:** 見出しに年と月（「2026年11月」/ "November 2026"）、曜日の行、日付のマス（6 週分まで）。**今日の日付に丸**。
  前後の月の日付は出さないか、薄く出す（どちらでもよいが、今日の丸と見分けがつくこと）。
- 日曜は赤、土曜は青（2×1 と 3×3 の曜日と日付）。祝日は今回は扱わない。
- 週の始まり: オプション `weekStart`（`sunday` / `monday`、既定は `sunday`）。ほかの値は断る。ほかのオプションは無し。
- 日付と曜日は端末（スマホ・PC ウインドウ）の時計で決める。PC から何も取りに行かない（予定のデータも API も無い）。
- 日付が変わったら自動で次の日に動く（時計の部品と同じく、画面側で日付の変わり目を見て描き直す。スリープから戻ったときも）。
- 文字の大きさはマスの大きさに合わせる（今の時計の部品と同じ作り）。3×3 の月はスマホの幅 320px でも崩れないこと。
- 押しても何もしない。指示書 23 のスワイプはこの部品の上からもできる。

## 2. 作り

- `web/v4/widgets/calendar.js` を作り、`registry.js` に登録する（今の時計の部品と同じ作り）。
  週・月のマスの計算は別の小さなファイル（例: `web/v4/widgets/calendar-days.js`）にして node でテストする。
- PC 側（C#）は `WidgetRegistry` の種類・大きさ（`1x1` `2x1` `3x3`）・オプションの検査だけ。テスト（C#）を足す。
- カタログの「部品」に「カレンダー」を置く。サイズは 1×1（今日）/ 2×1（週）/ 3×3（月）から選ぶ（ボタンの表示も「1×1 今日」のように中身が分かるように）。
  説明（カタログ）: 「今日の日付・今週・今月を表示します」。指示書 25 のボタンの説明にも出る。
- 詳細欄: 「週の始まり」（日曜 / 月曜）。
- 設定のプレビューでも本物の今日の日付で出す。

## 3. テスト

- node: 週の7日（週の始まり日曜・月曜、月・年をまたぐ週）、月のマス（うるう年の2月、月の1日が日曜・土曜、6 週になる月）。
- UI テスト（`tests/v4-widgets-ui.cjs`）: 3つの大きさの表示、今日に丸があること（日付を固定して確かめる）、日付が変わると描き直すこと（時計を進めて確かめる）、
  日本語・英語の曜日と月の表記、320px のスマホで 3×3 が崩れないこと。
- 既存のテストをすべて通す（`tests/run-unit.ps1`、`node tests/*.mjs`、`tests/v4-*-ui.cjs`、`test.ps1`）。
