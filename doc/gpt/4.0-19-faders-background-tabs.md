## 0. 先に直す不具合: プリセットのプレビューが細い線になる

プリセットを押すと、プレビュー欄が高さ 6px ほどの細い線になり、ボタンが見えない（Hiro の画面で確認。クロも再現した）。

原因: `.settings-preview-column` は `grid-template-rows: 48px 42px minmax(0, 1fr)` の3段。
プリセットの見本の間、`settings-app.js` の `presetPreview()` が2段目の `layoutTools`（ページと枠数）を `hidden` にするので、
プレビュー（`#settings-preview`）が2段目の 42px に繰り上がり、上下の padding 18px を引いて 6px になる。
UI テストは見本のボタンの数だけを見ていて、大きさを確かめていなかった。

直し方:
- `#settings-preview` を常に3段目に置く（`grid-row: 3`）か、`layoutTools` を `hidden` ではなく `visibility: hidden` にする。どちらでもよい。
- UI テスト: プリセットを押したあと、プレビューの画面（`.settings-preview-screen`）の高さが 150px 以上あり、縦横比が枠数どおりであること。
  テスト用のプリセットは本物（`DeckPresets.Public()`）と同じ形にして、時計・天気・PC 情報とフェーダーを含める。

## 1. 先に直す不具合: カタログのサイズ選びが部品ごとの決まりと合っていない

時計を押すと「デジタル時計」「アナログ時計」の両方に 2×1 と 2×2 が出る。アナログ時計は 2×2 しか置けない（PC 側の `WidgetRegistry` で 2×1 は断られる）。
また「デジタル時計（横長）」が別の項目として残っていて、サイズ選びと重なっている。説明の欄にも「2×2」と固定の大きさが出ている。

原因: `catalog.js` の `sizes()` は部品の種類（`clock` など）の `sizes` をそのまま出していて、スタイル（デジタル・アナログ）や
表示の種類（天気の「今」と「数日」など）ごとの決まりを見ていない。

直し方:
- カタログの項目ごとに置ける大きさを決める。PC 側の `WidgetRegistry.ValidateAndNormalize` の検査と必ず一致させる（画面側に同じ表を持つなら、C# と JS の両方のテストで突き合わせる）。
- 同じ部品で大きさだけが違う項目は1つにまとめる（例: 「デジタル時計」1つで 2×1 / 2×2）。中身が違うもの（天気の今・数日、PC 情報の1項目・まとめ）は別の項目のままでよい。
- 置ける大きさが1つだけの項目（アナログ時計など）はサイズのボタンを出さず、ダブルクリックやドラッグで1回で置ける。
- サイズのボタンを出す項目は、説明の欄に固定の大きさを書かない。
- 「最近使った」に古い項目の id（例: `widget-clock-digital-wide`）が残っていても壊れないこと（まとめた項目へ読み替えるか、黙って外す）。
- UI テスト: アナログ時計にはサイズのボタンが無く 2×2 で置ける。デジタル時計は 2×1 / 2×2 を選べる。すべての部品で、出したサイズが PC に断られないこと。

## 2. 音量フェーダーをほかの部品と同じ扱いにする

今のフェーダーは「向きごとに1本ずつあって、ページごとに隠す」作りで、ほかの部品と扱いが違う（詳細欄の「このページで隠す」など）。
Hiro の希望: ほかの部品と同じように、カタログから置き、詳細欄の「削除」で消せるようにする。

- 画面の動き:
  - カタログの「スピーカーフェーダー」「マイクフェーダー」は、ほかの部品と同じく今のページに置く（ダブルクリック・ドラッグ・サイズ選び）。置ける大きさは今のフェーダーの決まり（1×1、2×2、3×1、4×1、3×2、4×2 と縦長の向き違い）のまま。
  - 詳細欄はほかの部品と同じ並び。「このページで隠す」は無くし、ほかの部品と同じ「このボタンを削除」で今のページから消す。
  - Delete キー、「元に戻す」、ドラッグでの移動もほかの部品と同じに動くこと。
  - 1ページに置けるのはスピーカー・マイクそれぞれ1本まで（2本目を置こうとしたら、今ある方を選んで知らせる）。
- データ: v3 の設定ファイルの形（`faders` と各ページの `faders`、`off` / `hidden`）は、4.1 の作り直しまで変えない。画面の操作を今の形に置き換えるだけにする。
  - 置く: そのページにだけ表示する（ページの `faders` に置き場所を入れる）。
  - 削除: そのページで隠す（ページの `faders` に hidden）。
  - 「すべてのページから消す」の操作は画面から外す（データの `off` は読み込みのために残す）。
- 既存の設定（3.1 から上げた人、ページごとに隠している人）の見え方が変わらないこと。C# のテストで確かめる。

## 3. 「見た目」タブを「背景」にし、アイコンパックを別のタブにする

- 左のナビの「見た目」を「背景」（英: Background）に変える。中身は背景の設定だけにする。
- アイコンパック（読み込み・名前を変える・書き出し・削除）とアイコンの一括変更を、新しいタブ「アイコンパック」（英: Icon packs）に移す。
  並びは 配置 / プリセット / 背景 / アイコンパック / 保存 / 接続 / PC画面 / 全般。
- `&section=` の名前も合わせる（`appearance` は `background` に変える。古い `appearance` で開かれたら `background` を開く）。
- 「背景」「アイコンパック」とも、幅 1100px の日本語・英語で文字が切れないこと。

## 4. 背景の画像の反転と回転

背景に画像を使っているとき、画像を左右反転・上下反転・回転できるようにする。

- 背景タブの画像の調整のところに、ボタンを4つ置く: 「左右反転」「上下反転」「左に回す」「右に回す」（回転は 90 度ずつ）。
- 向き（横・縦）ごとに別々に覚える。今の位置（`x`, `y`, `zoom`, `fit`）と同じ所（`BackgroundPosition`）に `flipX`, `flipY`, `rotate`（0/90/180/270）を足す。
  PC 側で値を検査し、ほかの値は断る。古い設定には無いので、無いときは反転なし・0 度として読む。
- スマホ画面・PC ウィンドウ・設定のプレビューのすべてで同じ見え方になること。90 度・270 度のとき、画像の縦横を入れ替えて「全体を覆う / 全体を入れる」と位置・ズームの計算を合わせる。
  プレビューでのドラッグとホイールのズーム（`background-adjust.js`）も、回した後に指の動きと画像の動きが逆にならないこと。
- 「保存」タブのルック（見た目の保存）とバックアップにも反転・回転が入り、戻せること。
- テスト: C#（値の検査、古い設定の読み込み、保存と復元）、UI（ボタンで値が変わり保存される、回したあとドラッグで正しい向きに動く、スマホ画面の表示が同じ）。
