## 1. 不具合: サイズのボタンで部品を置くと保存できず、左上のマスが使えなくなる

手順: カタログで縦ホイールの「1×1」「1×2」を続けて押す →「保存できなかったので元に戻しました：null を値型に変換できません。」→ 以後、左上のマスに何も置けない。
サイズのボタンで置くものすべて（時計、天気、テンキーなど）で起きる。

原因: サイズのボタンは `catalog.add(action, null, size)` を呼ぶ。`add()` は `this.editor.addItem(..., cell && cell.row, cell && cell.column)` を呼ぶので、
`cell` が `null` のとき `row` と `column` に `null` が渡る。`editor-state.js` の `addItem()` は `row === undefined` のときだけ空きを探すので、
`row: null, column: null` の部品ができ、PC が数値に変換できず 400 で断る。
画面側では `null` の位置が左上として扱われ、その部品が左上を使っていることになるので、ほかの部品が置けなくなる。

直し方:
- `add()` は `cell` が無いとき `undefined` を渡す。`addItem()` も `row == null`（null と undefined の両方）で空きを探すようにする。
- 画面側の検査（`deck-rules.js` / `validOrientation`）で、位置や大きさが整数でない部品があれば保存に出さない。
- UI テスト: サイズのボタンで置いた部品の `row` `column` が整数で保存されること。続けて2つ置けること。上の「偽の PC の検査」を入れる。

## 2. 不具合: 新しいページにフェーダーが付いてくる

「+」でページを足すと、スピーカーとマイクのフェーダーが付いてくる。新しい盤面ではフェーダーを置かない決まり（指示書 17）なので、新しいページも同じにする。

原因: `editor-state.js` の `addPage()` は `{ name: '', faders: null, items: [] }` を足す。`faders: null` は「向き全体の置き場所を使う」意味なので、向き全体のフェーダーが出る。

直し方: 新しいページは、そのページでフェーダーを隠した状態（`speakerHidden: true, micHidden: true`）で作る。
カタログからフェーダーを置けば、そのページにだけ出る（指示書 19 の動き）。UI テストで確かめる。

## 3. 不具合: プリセットの「このページに使う」を押しても画面に出ない

Hiro の画面で、「このページに使う」を押しても画面に反映されなかった。Hiro は枠数（行・列）が合っていないためではと考えている。クロは原因を突き止められていない。

- まず本物の PC（C# の `PageController.ApplyPreset` と `DeckPresets` / `CustomPresets`）で再現する C# テストを書く:
  横・縦それぞれ、枠数が同じ場合と違う場合、ほかのページにボタンがある場合、そのページでフェーダーを隠している場合、自分のプリセットの場合。
  使ったあと `GET /api/v3/deck` で、そのページにプリセットのボタンが入っていることを確かめる。
- 画面側の流れ（`presets.js` の `apply()` → `server-change.js` の `run()` → `reload()` → `setPage()`）も確かめる。
  疑わしい所: `run()` の最初の `settle()`（未保存の変更を先に保存する）が失敗すると、「保存されていない変更があります」と出して何もしない。
  上の 1 の不具合で保存が失敗した状態だと、ここで止まっている可能性がある。
- 原因が分かったら直し、何が原因だったかをコミットメッセージに書く。

## 4. スピーカー・マイクのフェーダーのアイコン

フェーダーのミュートのボタンが「◖」「♩」の文字で、半分切れたように見える。3.1 では線で描いた絵（SVG）だった。

- 3.1 の絵に戻す（`git show develop/3.1:web/app.js` の `speakerIcon` / `micIcon`）。`fader.js` で `innerHTML` を使わず、SVG の要素を作って入れる。
- ミュート中は 3.1 と同じく分かる見た目にする（色を変える、または斜線）。

## 5. フェーダーにも見た目の設定を付ける

ボタンにある見た目の設定を、フェーダーの詳細欄にも付ける。

- 「ボタンの透け」（背景の透け具合）、「名前を隠す」に当たるもの（フェーダーは数値の表示を隠す）、アイコンの色。
- 保存先はフェーダーの置き場所と同じ所（向き全体とページごとの `faders`）。PC 側で値を検査する。古い設定に無いときは今の見た目。
- スマホ画面・PC ウィンドウ・設定のプレビューのすべてに反映する。

## 6. ページが多いときに分かりにくい

ページを増やすと、上のページのタブが「ペー…」と縮んで、どれが何ページか分からない（Hiro の画面で 7 ページ）。

- タブは縮めすぎない（最小の幅を決める）。入りきらないときは横にスクロールでき、今のページが見える位置まで自動で動く。
- タブには必ず番号を出す（「1」「2」…）。名前を付けたページは「1 配信」のように番号と名前。
- タブの列の右端に「ページ一覧」ボタンを置き、全ページの番号・名前・ボタンの数を縦に並べて選べるようにする。ここからも名前を変える・削除・移動ができる。
- ページの削除は今も各タブの「…」と右クリックにあるが、Hiro が見つけられなかった。「…」の中で削除が分かるよう、一覧にも削除を置く。

## 7. PC ウィンドウの選択中の色

PC ウィンドウで、選んでいる方が白、選んでいない方が背景と同じ色で、見にくい。

- 切り替えのボタン（向き、ページ、メニューの選択肢など、PC ウィンドウにある選択の表示すべて）を見直す。
- 選んでいる方は強調の色（`--color-accent`）で塗り、文字は白。選んでいない方は背景より少し明るい色と枠線で、押せることが分かるようにする。
- 設定ウィンドウの同じ種類のボタン（横向き・縦向きなど）と同じ見え方にそろえる。明るい背景・暗い背景の両方で文字が読めること。

## 8. アイコンパックの一覧を読み込み方で分ける

アイコンパックのタブの一覧で、`.tpicons`（や `.zip` / `.streamDeckIconPack`）のパックファイルから読み込んだものと、画像を選んで作ったものの間に線を入れて分ける。

- 読み込んだときに、どちらから作ったかをパックに覚える（`source: "file"` / `"images"`）。古いパックで分からないものは「パックファイル」側に入れる。
- 見出しを付ける: 「パックファイルから読み込んだもの」「画像から作ったもの」（英: From pack files / Made from pictures）。
