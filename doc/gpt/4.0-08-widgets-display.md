## 3. やること

### 3.1 部品の仕組み

4.1 で「再生中の音楽のジャケット」などの部品を足す予定です。**部品を1種類足すときは、クラスを1つ書いて部品表に1行足すだけ**で済む形にしてください。

- `web\v4\widgets\registry.js`：`type` → 部品クラス の表（`export const widgetTypes = { clock: ClockWidget, … }`）。
- 部品クラスの形（全部品で同じ）：
  - `constructor(context)`：`context` は `{ api, i18n, feedback, viewId }` など、部品が使ってよいものだけ。
  - `mount(node, item, state)`：`node` は 07 の `DeckGrid` が場所を決めた枠。中身を作る。
  - `update(state)`：音量・PC情報・天気などが変わったとき。**作り直さずに中身の数字や見た目だけ変える**。
  - `destroy()`：タイマー・イベント・送信待ちを止める。
- フェーダーは「部品」ではなく向き・ページの `faders` から出るが、同じ形のクラスにする（表には `type` の代わりに `speaker`/`mic` で入れてよい）。
- 部品表にない `type`（09 で作る `wheel`・`touchpad`・`keypad`）は 07 と同じ「準備中」の枠のまま。
- **描き直しを減らす**（大事）：今の 07 は状態が届くたびにグリッドを全部作り直している。これだとフェーダーを動かしている最中に消えたり、時計が点滅したりする。
  - グリッドを作り直すのは、**配置が変わったとき（`version`）・ページ・向き・言語が変わったとき**だけ。目印（シグネチャ）を比べて決める。
  - それ以外の更新では、表示中の各部品の `update(state)` を呼ぶだけ。
  - フェーダーを指で動かしている間は、その部品の `update` で値を上書きしない（今の `audioInteraction` と同じ考え方）。
  - 作り直すときは、前の部品の `destroy()` を必ず呼ぶ。

### 3.2 フェーダー

今の `audioFaderV104` と同じ動き（古い `audioFader` の中身は使われていないので手本にしない）：

- 縦・横（枠が横長なら横）、`speaker`/`mic` のアイコン、ミュートボタン、音量の数字。使えない機器のときは押せない見た目。
- 指で動かす間は80ms 間隔にまとめて `{ target, volume }` を送り、指を離したら `{ target, volume, final: true }` を1回。前の送信が返るまで次を送らない（今と同じ）。
- ミュートボタンは `{ target, toggleMute: true }`。
- 応答の `audio` をすぐ反映。失敗したら下に短く表示し、状態を読み直す。
- `pointerdown` で `setPointerCapture`。フェーダーの上ではページ送りのスワイプが起きないこと。

### 3.3 表示の部品

- **時計**（`clock`）：`options` のデジタル・アナログ、2×1・2×2 を今と同じに。端末の時計で動かし、PC へは何も送らない。見えていない間（画面が隠れた）はタイマーを止める。
- **天気**（`weather`）：1×1 は今の天気、2×2 は3日分と出典。場所が未設定なら「PCの設定画面で場所を決めてください」。
- **PC情報**（`metrics`）：CPU・メモリ・GPU・GPU メモリと、`options` で選んだ表示・履歴グラフ。値は状態の `metrics` から。グラフは `<canvas>` かコードで作る SVG（ライブラリは使わない）。
- **スライドショー**（`slideshow`）：今と同じ間隔・順番で `GET /api/slideshow` から画像を取って切り替える。画面が隠れたら止める。画像の `src` は `data:image/` か同じサーバーのパスだけ。
- 各部品の名前の出し方（`appendWidgetName`）も今と同じ。

### 3.4 表示中の部品を PC に知らせる

PC情報は、表示している端末があるときだけ PC が集めます（`DisplaySubscription`）。

- `web\v4\core\view.js`（`ViewAnnouncer`）：今のページ・向きで見えている部品の id の並びが変わったら `POST /api/view` `{ viewId, visibleIds }` を送る（同じ並びなら送らない。今の `announceView` と同じ）。
- 07 の `SyncLoop` に渡している `visibleIds` も、ボタンを含めた全部ではなく、**部品の id だけ**にする（今の `visibleWidgetIds` と同じ）。
- 接続を切ったとき・画面が隠れたときは、今と同じく空の並びを送る。

### 3.5 背景

- `web\v4\deck\background.js`（`DeckBackground`）：状態の `background` に合わせて、背景色・背景画像（`GET /api/background/image`）・位置・ボタンの透け具合を今と同じに描く（`applyBackgroundState`・`paintBackground`・`paintKeys`・`keyShade` の考え方）。
- 画像は `background` の中身（リビジョンなど）が変わったときだけ取り直す。
- 色の計算（`hexRgb`・`mixRgb`・`lightness` など）は `background.js` の中か、小さな `color.js` に分ける。

### 3.6 接続の申請

07 では「接続されていません」と出すだけでした。今の画面と同じ申請の流れを入れます。

- 「接続されていません」画面に、端末名の入力（初期値は言語ファイルの「スマートフォン」）と「接続をリクエスト」ボタン。
- 押すと `POST /api/pair/start` `{ name }`。返ってきた確認番号を大きく出し、「PCで同じ番号を確認して『許可』を押してください（3分以内）」。
- 2秒ごとに `GET /api/pair/status?id=…`（`Authorization: Bearer <secret>`）。`approved` なら `token` を `KeyStore` に保存してそのまま画面を出す。`denied` なら「PCで接続が拒否されました」。期限切れなら「期限が切れました。もう一度リクエストしてください」。画面が隠れている間は止める。
- QR を読んで `#connect=` で来た場合は、07 のとおり申請なしでつながる。
- クラスは `PairingScreen`（`web\v4\phone\pairing.js`）。通信は 07 の `Api` を使い、申請用の `secret` を渡せるようにする（`Api` に Bearer を差し替えた複製を作る小さなメソッドを足してよい）。

### 3.7 押した感触

- `web\v4\core\feedback.js`（`Feedback`）：`tap(strong)`。設定（`tapoard-feedback`）がオンなら、振動できる端末は `navigator.vibrate`、できない端末（iPhone）は Web Audio の短いクリック音（今の `playClick` と同じ音）。35ms より短い間隔では鳴らさない。
- 音は最初に触ったとき（`pointerdown`）に準備する（iPhone は触るまで音を出せないため）。
- 07 の `PhoneApp.press` の振動、フェーダーの操作をこれに置き換える。

### 3.8 テスト

- `tests\v4-widgets-ui.cjs`（07 の `v4-phone-ui.cjs` と同じ偽サーバーの作り。`locale: 'ja-JP'` と wakeLock の差し替えも同じに）：
  - フェーダーを下から上へ動かすと `/api/audio` が数回飛び、最後の1回だけ `final: true`。動かしている最中に偽サーバーが音量の違う状態を返しても、指の位置の値のまま。
  - ミュートボタンで `{ target, toggleMute: true }`。
  - 同期で `metrics` だけ変わったとき、**グリッドが作り直されない**（部品の DOM 要素が同じものであることを確かめる）。`version` が変わったら作り直される。
  - 時計が端末の時刻を出す（Playwright の `clock` か `page.evaluate` で確かめる）。
  - PC情報の部品があるページを開くと `/api/view` にその id が入る。部品のないページへ移ると空になる。
  - 天気：場所あり・なしの表示。スライドショー：`/api/slideshow` を順に呼ぶ。
  - 背景：背景色と画像が付く。画像は `background` が変わらない限り1回しか取らない。
  - 接続の申請：キーなし → 端末名を入れてリクエスト → 確認番号が出る → 偽サーバーが `approved` を返す → `tapoard-key` に保存されボタンが出る。`denied` の場合も確かめる。
  - `wheel` などはまだ「準備中」の枠。
  - コンソールにエラーがない。幅 320px で横スクロールなし。
- 07 の `v4-phone-ui.cjs` も通ること（必要なら期待値を直してよいが、確かめる内容は減らさない）。
- `tests\i18n-test.mjs` が通ること（キーが増えても ja と en が一致）。
