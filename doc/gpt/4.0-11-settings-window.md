## 3. やること

### 3.1 設定ウインドウ（C#）

- 新しい `SettingsWindow`（`src\SettingsWindow.cs`）：ふつうのタイトルバー付きのウインドウ（`Form`）。題名「TaPoard 設定」、大きさを変えられる、最小 1100×700、最初は画面の 80%（最大 1440×900）で中央。中に `WebView2Host` を1つ置いて、ウインドウいっぱいに広げる（`PcWindow` の WebView2 の使い方を手本に。ただし PcWindow の枠なし・移動・帯の仕組みは持ち込まない）。
- 開く URL：`http://127.0.0.1:<port>/v4/settings.html#admin=<管理者キー>`（`admin` は今と同じ起動ごとのキー）。
- 1つだけ開く。開いていれば手前に出す。閉じたら破棄。WebView2 のデータフォルダは PC ウインドウと同じ親の下に別フォルダ。
- WebView2 が入っていない PC（`PcWindowService.RuntimeAvailable` が false）では、今までどおりブラウザで `/settings` を開く。
- トレイ：
  - ダブルクリックと、一番上に「設定を開く」→ 設定ウインドウ。
  - 今の「設定をブラウザで開く」は「古い設定画面をブラウザで開く」に名前を変えて残す。
  - 「PC 用ウィンドウの設定」は今のまま（13 で設定ウインドウに移す）。
- PC ウインドウの歯車（`PcWindowService.OpenSettingsPage`）→ 設定ウインドウを開く。
- 同じクラスの中で `Process.Start` などを直接呼ばず、今の `IDesktop`/`AppHost` の考え方に合わせる（テストのない UI 部分なので最小限でよい）。

### 3.2 設定画面の骨組み

- `web\v4\settings.html`：`/v4/style/*.css` と `web\v4\style\settings.css`、`<script type="module" src="/v4/settings/app.js">`。
- 管理者キー：`#admin=<キー>` を `sessionStorage` の `tapoard-admin` に入れてハッシュを消す（`KeyStore` に管理者用の読み方を足すか、小さな `AdminKeyStore` を作る）。キーが無ければ「TaPoard のトレイから設定を開いてください」とだけ出す。
- 画面の作り（モックどおり）：
  - 上：「TaPoard 設定」と接続の状態（「スマホ1台・PC ウインドウが接続中」など。`/api/v3/state` の `phoneConnected`・`pcWindowOpen` から）。
  - 左の縦の列：配置・見た目・保存・接続・PC画面・全般。**今回は「配置」だけ動く**。ほかは押すと「この画面は次の更新で使えるようになります。今は古い設定画面（トレイの『古い設定画面をブラウザで開く』）を使ってください」と出す。
  - 「配置」の中：左に追加できるもの（3.6）、真ん中にプレビュー（3.4・3.5）、右に選んだボタンの設定（3.7）。
- 07 の `SyncLoop` で `/api/v3/state` を待ち、ほかの所（古い設定画面・プリセットなど）で配置が変わったら（`version` が変わったら）読み直す。**編集中で保存していない変更があるときは上書きせず**、「ほかの所で設定が変わりました。読み直す / このまま続ける」の帯を出す。
- 幅 1100px で全部が収まる（横スクロールなし）。

### 3.3 編集のしくみ

- `EditorState`：`GET /api/v3/deck` で読んだ `deck` と `version` を持つ。編集はすべてこのクラスのメソッド（`moveItem`・`addItem`・`removeItem`・`updateItem`・`addPage`・`movePage`・`removePage`・`renamePage`・`setGrid`・`moveFader` など）を通し、変わったら知らせる。**DOM を触らない**（node のテストで動かせるように）。
- 位置の検査（枠の中か・重ならないか・その type で使える大きさか）は `EditorState` の中の小さな関数で行い、だめな操作は受け付けない（サーバーにも 10 の検査があるが、画面でも先に止める）。
- `Saver`：変更があってから 600ms 待って `POST /api/v3/deck` `{ baseVersion, deck }`。保存中にさらに変わったら、終わってからもう一度。成功したら `GET /api/v3/deck` で読み直して `version` と新しい id を受け取る（新しく足したボタンの id はサーバーが付け直すため。選んでいたボタンは位置で選び直す）。
  - 409：「ほかの所で設定が変わりました」の帯（読み直す）。400：サーバーの `error` をそのまま出し、最後に保存できた状態に戻す。
  - 画面の下に「保存しました / 保存中… / 保存できませんでした」。
- `History`：元に戻す・やり直す（`Ctrl+Z`・`Ctrl+Y`、50 回まで）。上の「元に戻す」ボタンも。元に戻した結果も保存する。
- `deck.background` は送るが、サーバーは使わない（10 のとおり）。

### 3.4 プレビューと配置の操作

- 向きの切り替え（横向き・縦向き）。プレビューの形は列×行の比。
- ボタン・部品は 07〜09 の `DeckGrid` と部品で描く（スマホと同じ見た目。背景も 08 の `DeckBackground` で）。ただし**プレビューでは押しても PC に何も送らない**：`DeckGrid` に「プレビュー」の指定を足し、ボタンを押したら選ぶだけ、フェーダー・ホイール・タッチパッド・テンキーは入力を受け付けない（時計・天気・PC情報は今の値を出してよい）。
- 空いているマスは薄い枠で「空き」と出す。
- 選ぶ：クリック。選んだものは枠を強調し、右の設定に出す。`Delete` キーで削除（元に戻せる）。
- 動かす：ドラッグで別のマスへ。置けない所（はみ出す・重なる）は赤く出して離しても動かない。フェーダーも同じように動かせる。
- 一覧から追加：一覧の項目をプレビューへドラッグして置く、またはダブルクリックで今のページの最初の空き（なければ「空きがありません」）。
- スマホと同じく、プレビューで使う文字はすべて言語ファイルから。

### 3.5 ページと枠数

- プレビューの上にページのタブ（モックどおり）：ページ名（10）を出す。名前が空なら「ページ 1」。
  - ＋ でページを足す（今のページの後ろ）。
  - ダブルクリックで名前を変える（20 文字まで、Enter で決定、Esc でやめる）。
  - ドラッグで順番を変える。
  - 右クリック（または「…」）で「名前を変える / 前へ / 後ろへ / 削除」。削除は確認を出す（元に戻せる）。
- 枠数：列・行の選択（2〜8）。小さくしてはみ出すボタンがあるときは「N 個のボタンが入りません。空いている所へ並べ直しますか？」と聞き、「はい」なら同じページの空き → 後ろのページの空き → 新しいページ の順に移す（`EditorState` の中で。サーバーは動かさないため）。「いいえ」なら変えない。
- フェーダー（スピーカー・マイク）：ページごとの表示・非表示と大きさは右の設定で（3.7）。

### 3.7 選んだボタンの設定（基本の項目）

モックの右の欄。今回入れるのは：

- 名前（3 行・80 文字まで）、押したときの動き（読むだけの説明。ショートカットならキーも）。
- 大きさ（その type で使える大きさだけ選べる。広げて重なる・はみ出すなら選べない）。
- 文字の大きさ・アイコンの大きさ・文字の濃さ・ボタンの透け（今の設定画面と同じ範囲）、名前を隠す。
- URL ボタンの URL、テキストのコピーの文字、アプリの `path`・`args`（入力欄だけ。ファイルを選ぶ画面は 13）。
- フェーダーを選んだとき：このページで隠す、大きさ。
- 「このボタンを削除」。
- アイコンを変える・色を変える（12）、好きなキー・部品ごとの詳しい設定（13）は、押すと「次の更新で使えるようになります」。
