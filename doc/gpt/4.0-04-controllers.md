# 依頼書 4.0-04：API の処理を Controller クラスに分ける

TaPoard 4.0 作り直しの段階2（後半）です。03 でルート表ができたので、今回は表の先にある**処理の中身**を `Program` から出して、領域ごとの **Controller クラス**に移します。Controller が使う共有の状態（設定・ページ番号・同期など）は **`AppState` クラス**にまとめ、Controller は `Program` を直接触らない形にします。

**動きは 3.1 とまったく同じ**です。処理の中身（設定の変え方、返す JSON）は書き換えず、置き場所と状態の持ち方だけを変えます。

ページや配置のロジックを Service に分けるのは、設定 v3 で中身を作り直すとき（段階4）にまとめて行います。今 v2 の形のまま Service を作ると、v3 でまた作り直しになるためです。

## 0. 作業の始め方

1. `develop/4.0` を最新にする（03 がマージ済み。先頭はこの依頼書のコミット）。
2. `develop/4.0` から `gpt/4.0-04-controllers` を切って作業する。
3. 終わったらこのブランチのまま止める（マージと push はレビュー後に Claude が行う）。

## 1. 必ず守ること（01〜03 と同じ）

- **C# 5 で書く**（`$"..."`、`?.`、`nameof`、`=>` メソッド、自動プロパティの初期値、`using static`、`when` は使わない）。ビルドは `v4.0.30319\csc.exe`。
- **外部パッケージを入れない。新しい .cs は `src\` 直下に置く**（サブフォルダーはビルドされない）。
- **動き・API・JSON・設定ファイルを変えない。web\ は触らない。** URL、権限、ステータスコード、返す JSON、エラーメッセージを今と同じにする。03 の `ApiRouteTableTests`（45本の表）と `ApiStatusTests` は**中身を変えずに**通ること（型名の変更に合わせた修正だけはしてよい）。
- **ロックは今と同じ1つだけ。** `Program.Gate` を `AppState.Gate` に移すだけで、ロックを取る場所・範囲は変えない。新しいロックを足さない。
- **リフレクションで使う名前**：`Program` のフィールド `admin`、`lan`、`api`、メソッド `Handle`、`SplitOrientationApps`、`UseHost`、`UseStore` は残す。`config`・`store`・`Launch`・`VolumeKey`・`ApplyAudio`・`Save`・`ValidateEntry` は今回移すので、**テストの方を新しい場所に合わせて直す**（3.6 を見る）。
- **個人情報を入れない。** 作者は `TaPoard Developer <353783363+Mimi1011-hub@users.noreply.github.com>`。
- 1つのまとまりごとに小さく commit する（英語1行）。途中のコミットでもビルドが通るようにする。

## 2. 出来上がりの形

```
Program（起動・トレイ・接続の受付・UI スレッドの仕事だけ）
  ├─ AppState            共有の状態（設定・ページ・同期・元に戻す・保存先・ホスト）
  ├─ ApiRouter<ApiRequest> ← 各 Controller が Register で自分のルートを登録
  └─ ProgramDesktop : IDesktop   UI スレッドが要る操作（PC ウインドウ・インポート窓）

PairingController / DeckController / PageController / LookController / InputController / SystemController
  → AppState と（必要なら）IDesktop だけを使う。Program は参照しない。
HttpIO（応答の書き出し・入力の読み取り）
```

## 3. やること

### 3.1 リクエストを外に出す（`src\ApiRequest.cs`）

- `Program.Request` を、トップレベルの `sealed class ApiRequest` に移す（フィールドは今と同じ：stream、method、target、path、headers、remote、local、auth、isAdmin、allowed、input、json）。
- `ApiRouter<Program.Request>` は `ApiRouter<ApiRequest>` になる。テストの型名も合わせる。

### 3.2 応答と入力の共通処理（`src\HttpIO.cs`）

`static class HttpIO` に、今 `Program.Http.cs` / `Program.cs` にある次のものを**中身を変えずに**移す。

- `JsonType`、`Reply`、`ReplyJson`、`ReplyBytes`、`WriteResponse`、`ReadInput`、`QueryValue`、`Json`

`Program.Http.cs` には `Accept`、`Handle`、`ReadRequest`、`Authenticate`、`ServeFile`、`Line`、`PublicFiles` を残し、これらは `HttpIO` を呼ぶ。

### 3.3 共有の状態をまとめる（`src\AppState.cs`）

```csharp
// API・トレイ・PC ウインドウが共有する状態。読み書きするときは Gate を持っていること。
sealed class AppState
{
    internal readonly object Gate = new object();
    internal readonly SyncHub Sync;          // new SyncHub(Gate)
    internal readonly PageUndo Undo = new PageUndo();
    internal readonly string Root, Data, AppVersion;
    internal AppHost Host;
    internal ISettingsStore Store;

    internal Settings Config;
    internal string Version;                 // 今の Program.version（ボタン一覧が変わると新しい ID）
    internal int LandscapePage, PortraitPage;
    internal string ImportId;
    internal object ImportResult;

    internal AppState(string root, string data, string appVersion, AppHost host, ISettingsStore store);
    internal void Save();                    // Store.Save(Config)
    internal void Signal();                  // Sync.Signal()
    internal void NewVersion();              // Version = 新しい ID
    internal void TouchPhone(bool localRequest);
    internal bool PhoneConnected { get; }
}
```

- `Program` に `internal static readonly AppState State = new AppState(Root, Data, AppVersion, AppHost.CreateWindows(), new FileSettingsStore(Data));` を置き（`Root`・`Data`・`AppVersion` より後ろ）、`Program` のフィールド `config`、`version`、`landscapePage`、`portraitPage`、`importId`、`importResult`、`sync`、`pageUndo`、`store`、`host`、`Gate` を**消して** `State.…` に置き換える。
- `UseHost` / `UseStore` は残し、`State.Host` / `State.Store` を差し替える。
- `api` は `State` より後ろで宣言する（static は書いた順に初期化されるため）。

### 3.4 UI スレッドが要る操作を interface にする（`src\Desktop.cs`）

Controller から WinForms や `ui.Invoke` を直接触らないよう、次の interface を作り、`Program` の中に実装クラス `ProgramDesktop` を置く（中身は今の Program のメソッドを呼ぶだけ）。

```csharp
interface IDesktop
{
    object PcWindowView();
    void SavePcWindow(Dictionary<string, object> input); // 今の SavePcWindow の中身（応答は Controller が書く）
    void OpenPcWindow(bool fullscreen);
    string StartImport();                                 // 窓を開いて ticket を返す（今の StartImport の UI 部分）
}
```

テストでは何もしない偽物を `tests\Fakes.cs` に足す。

### 3.5 Controller に分ける

それぞれ `sealed class XxxController`、コンストラクターで `AppState`（と必要なら `IDesktop`）を受け取り、`internal void Register(ApiRouter<ApiRequest> api)` で**今と同じパス・権限**のルートを登録する。ハンドラーは今の `Program` のメソッドを**中身そのまま**移し、`config` → `state.Config`、`Gate` → `state.Gate`、`ReplyJson` → `HttpIO.ReplyJson` のように置き換える。

| ファイル | 受け持つルート | 一緒に移すもの |
|---|---|---|
| `src\PairingController.cs` | /api/pair/start、/api/pair/status、/api/pair/manage（GET・POST）、/api/rotate | `RotateKeys`（トレイからも呼ぶので internal） |
| `src\DeckController.cs` | /api/ping、/api/state、/api/sync、/api/settings（GET・POST） | `GetState`、`WaitForSync`、`GetSettings`、`SaveSettings`、`ValidateEntry`、`ResolveAudioDevice`、`KeepServerFields`、`UpdateRuntimeSessions`、`RenewRuntimeSessions`、`ViewIdentity` |
| `src\PageController.cs` | /api/page、/api/page/move、/api/page/delete、/api/page/undo、/api/layout、/api/fader/remove、/api/presets/apply | `ReadOrientation`、`RequireOrientation`、`ShrinkCurrentPages`、`ApplyControlInput` |
| `src\LookController.cs` | /api/background*（GET の image を含む）、/api/icon-packs（GET・get・前方一致 POST）、/api/icon-styles（GET・前方一致 POST）、/api/backups、/api/backups/restore、/api/presets | `IconPackAction`、`IconStyleAction`、`SetBackground` |
| `src\InputController.cs` | /api/view、/api/input、/api/input/keepalive、/api/input/release、/api/audio、/api/action、/api/devices | `Launch`、`VolumeKey`、`ApplyAudio`、`SetAudio`、`RunAction` |
| `src\SystemController.cs` | /api/pc-window（GET・POST）、/api/pc-window/open、/api/firewall、/api/firewall/repair、/api/import（GET・POST）、/api/weather/search、/api/weather/location、/api/slideshow、/api/slideshow/pick-folder | — |

- 複数の Controller が使う**状態を持たない関数**（`Controls`、`ControlPages`、`Grid`、`IsType`、`NormalizeControlSlots`、`NewId` など）は `static class DeckView`（`src\DeckView.cs`）に置き、`Settings` を引数で受け取る形にする。
- `UpdateRuntimeSessions` など別の Controller からも使うものは、持ち主の Controller の `internal` メソッドにして、使う側にコンストラクターで渡してよい（例：`new InputController(state, deck)`）。
- `Program.Routes.cs` の `BuildApi()` は、Controller を作って `Register` を順に呼ぶだけにする。トレイから使う Controller（`RotateKeys` など）は Program の static フィールドに持ってよい。
- **Controller のファイルに `Program.` が出てこないこと**（終わりの条件 5）。

### 3.6 テストを直す・足す

- `tests\HostTests.cs`：`Launch`・`VolumeKey`・`ApplyAudio`・`Save` をリフレクションで探すのをやめ、**偽物のホストと `FakeSettingsStore` で作った `AppState`** から `new InputController(...)` などを作って直接呼ぶ（テストは src と一緒にコンパイルされるので internal を呼べる）。
- `tests\Release103Tests.cs` など `config` / `store` をリフレクションで触っているテストは `Program.State.Config` / `Program.State.Store` に直す。`ValidateEntry` を使うテストは `DeckController` を直接呼ぶ。
- `tests\ControllerTests.cs`（新規）：`FakeSettingsStore` と偽物のホスト・`IDesktop` で `AppState` と全 Controller を作り、`ApiRouter<ApiRequest>` に登録する。`ApiRequest` の stream に `MemoryStream` を入れて呼び、応答の本文を読んで確かめる。
  - `GET /api/state` が `revision` を返す
  - ページが2枚ある設定で `POST /api/page/delete` → ページが1枚になり、`FakeSettingsStore` に Save される → `POST /api/page/undo` → 2枚に戻る
  - `POST /api/audio`（volume、final: true）で偽物の SetVolume が呼ばれ、`Revision` が1増える
  - 実際の `data\` フォルダーに何も書かれない
- `tests\run-unit.ps1` に `ControllerTests` を足す。
