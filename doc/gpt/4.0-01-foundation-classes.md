# 依頼書 4.0-01：土台のクラス化（インターフェースと AppHost）

TaPoard 4.0 作り直しの段階1（前半）です。**動きは 3.1 とまったく同じ**のまま、Windows とやり取りする土台の部品にインターフェースを付けて、テストで偽物に差し替えられるようにします。

## 0. 作業の始め方

1. `develop/4.0` を最新にする。
2. `develop/4.0` から `gpt/4.0-01-foundation-classes` を切って、その上で作業する。
3. 終わったらこのブランチのまま止める（`develop/4.0` へのマージと GitHub への push はレビュー後に Claude が行う）。

## 1. 必ず守ること

- **C# 5 で書く**：ビルドは Windows 標準の `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（.NET Framework 4.x）です。次の書き方はコンパイルできないので使わない：`$"..."`（文字列補間）、`?.`、`nameof`、`=>` で書くメソッド・プロパティ、自動プロパティの初期値、`using static`、例外フィルター `when`。
- **外部パッケージ（NuGet など）を入れない。** 参照は今と同じ System.Windows.Forms / System.Drawing / System.Web.Extensions / System.Net.Http だけ。
- **新しい .cs ファイルは `src\` 直下に置く。** build.ps1 と tests\run-unit.ps1 は `src\*.cs` しか読まないので、サブフォルダーに置くとビルドされない。
- **動き・API・JSON・設定ファイルを変えない。** URL、返す JSON、settings-v2.json の中身、画面（web\ 以下）はそのまま。web\ は触らない。
- **テストが使っている Program の非公開メンバーの名前を変えない**：フィールド `config`、`admin`、`lan`、メソッド `Handle`、`SplitOrientationApps`、`ValidateEntry`（tests がリフレクションで呼んでいる）。
- **実機で直してきた処理の中身を書き換えない。** 今の static class（ShortcutKeys、NativeInput、AudioControl、AudioDevices、CustomActions、StartApps）の中身はそのまま残し、新しいクラスはそれを呼ぶだけにする。
- **個人情報を入れない**：コード・テスト・コミットに、名前・メールアドレス・`C:\Users\<名前>` のような個人のパスを書かない。コミットの作者は `TaPoard Developer <353783363+Mimi1011-hub@users.noreply.github.com>` にする（`git -c user.name=... -c user.email=... commit` で指定してよい）。
- 1つのまとまりごとに小さく commit する。コミットメッセージは英語で、何を変えたか1行で書く。

## 2. やること

### 2.1 インターフェースを作る（`src\Platform.cs`）

今の static class の `internal static` メソッドに合わせて、次のインターフェースを作る。メソッド名と引数は今の static メソッドと同じにする。

| インターフェース | 元にする static class | メソッド |
|---|---|---|
| `IKeySender` | ShortcutKeys | `Exists(action)`、`IsAudio(action)`、`RequiresDiscordFocus(action)`、`Actions()`、`Send(action)`、`Send(action, custom)`、`ValidateOverride(action, value)` |
| `IPointerInput` | NativeInput | `Send(NativeInputEvent[])`、`KeyTap(byte)`、`KeyCombo(byte[])`、`Release(keys, buttons)` |
| `IAudioService` | AudioControl | `Read()`、`SetVolume(target, value)`、`AdjustVolume(target, delta)`、`ToggleMute(target)` |
| `IAudioDevices` | AudioDevices | `List()`、`Validate(target, id)`、`Switch(target, id)` |
| `IShellActions` | CustomActions、StartApps、Process.Start | `OpenUrl(url)`、`CopyText(text)`、`IsStartApp(path)`、`StartApp(path)`、`StartProcess(path, args)` |

`StartProcess` には、今 `Program.Launch` の最後にある `Process.Start(new ProcessStartInfo(...){ UseShellExecute = .lnk のとき true, WorkingDirectory = ... })` をそのまま移す。

### 2.2 Windows 用の実装を作る（`src\Platform.Windows.cs`）

`WindowsKeySender : IKeySender` のように、各インターフェースの実装クラスを作る。中身は static class を呼ぶだけ（例：`public void Send(string action, string custom) { ShortcutKeys.Send(action, custom); }`）。

### 2.3 AppHost を作る（`src\AppHost.cs`）

```csharp
sealed class AppHost
{
    internal readonly IKeySender Keys;
    internal readonly IPointerInput Pointer;
    internal readonly IAudioService Audio;
    internal readonly IAudioDevices AudioDevices;
    internal readonly IShellActions Shell;

    internal AppHost(IKeySender keys, IPointerInput pointer, IAudioService audio, IAudioDevices audioDevices, IShellActions shell) { ... }

    // 本番用：Windows の実装で組み立てる
    internal static AppHost CreateWindows() { ... }
}
```

- Program に `static AppHost host = AppHost.CreateWindows();` を置く（テストが Program を初期化せずに呼んでも動くよう、宣言時に作る）。
- テストから差し替えられるよう、`internal static void UseHost(AppHost value)` を Program に用意する。

### 2.4 Program から使う

`src\Program.Api.cs` の次の場所だけ、static class の直接呼び出しを `host.…` に置き換える。

- `RunAction`：音量キー（`NativeInput.KeyTap`）
- `Launch`：`AudioDevices.Switch`、`ShortcutKeys.Send` / `IsAudio`、`CustomActions.OpenUrl` / `CopyText`、`StartApps.IsStartApp` / `Start`、`Process.Start`
- `SetAudio`：AudioControl の呼び出し

ほかのファイル（InputSessions.cs、ValidateEntry の中の検証など）は **今回は触らない**。次以降の依頼書で扱う。

### 2.5 テストを足す

- `tests\Fakes.cs`：各インターフェースの偽物。呼ばれた内容をリストに記録するだけで、Windows には何もしない。
- `tests\HostTests.cs`（`public static int Main()` を持つ）：偽物で組んだ AppHost を `Program.UseHost` で入れ、リフレクションで `Program.Launch` を呼んで確かめる。最低限：
  - hotkey のボタン → `IKeySender.Send(action, hotkey)` が1回呼ばれる
  - url のボタン → `OpenUrl` に URL が渡る
  - clipboard のボタン → `CopyText` に本文が渡る
  - audioDevice のボタン → `Switch(target, id)` が呼ばれる
  - .lnk / .exe のボタン → `StartProcess` が呼ばれ、実際のアプリは起動しない
- `tests\run-unit.ps1` の `$tests` に `HostTests` を足す。コンパイル行に `tests\Fakes.cs` も渡す（他のテストも一緒にコンパイルして構わない）。

## 3. やらないこと（後の依頼書で扱う）

Program の共有状態（設定・元に戻す・ペアリング）の分割、Controller／Service への分割、設定 v3、言語ファイル、画面（web\）の作り直し、古い互換（streamdeck-* など）の削除。
