## 1. 不具合: PC ウインドウで、ボタンの上からスワイプできない

Hiro の画面で「スワイプできるアイコンとできないアイコンがある」。

原因: 4.0 の PC ウインドウでは、スワイプは `web/v4/pc/pc-pointer.js` だけが扱う。`pointerDown()` は `empty(event.target)` のとき（空いている所と、
`INTERACTIVE` に入っていない時計・天気・PC 情報などの部品）だけ動くので、普通のボタン（`button.deck-button`）の上からはスワイプできない。
スマホ用の `web/v4/phone/swipe.js` は `phone-app.js` で `if (!this.pcWindow)` のときだけ作られるので、PC ウインドウでは使われない。
3.1 は、PC ウインドウでは空いている所のドラッグがウインドウを動かすので、わざと「ボタンの上から」スワイプする作りだった。

直し方:
- PC ウインドウでも、ボタンの上から左右にすばやく動かすとページが変わるようにする（3.1 と同じ判定: 900ms 以内、横の移動が `max(40, min(120, 幅の 8%))` 以上、横が縦の 1.5 倍以上）。
- スワイプになったときは、そのボタンを押したことにしない（今の `grid.js` の `bindPress()` の「10px 動いたら押さない」のままでよいか確かめる）。
- 空いている所と部品の上の今の動き（すばやく横ならスワイプ、それ以外はウインドウを動かす）は変えない。
- スマホと同じく、フェーダー・ホイール・タッチパッド・テンキーの上ではスワイプしない。
- メニューの「スワイプでページを移動」を切ったときは、どこからもスワイプしない（今の `tapoard-swipe` のまま）。
- UI テスト（`tests/v4-pc-window-ui.cjs`）: ボタンの上から横にすばやく動かすとページが変わり、ボタンの操作は送られない。フェーダーの上では変わらない。スワイプを切ると変わらない。

## 2. スワイプ中に画面が指について動き、次のページが横から入る

3.1 では、スワイプ中にボタンの盤面が指について横に動き（最初と最後のページの先では、ゴムのように少しだけ動く）、
指を離すと今のページが横へ抜けて、次のページが反対側から入ってきた。足りないときは元の位置に戻った。4.0 にはこれが無い（スマホも PC ウインドウも）。

直し方:
- 3.1 の `deckMotion()` / `swipeFollow()` / `swipeSnapBack()` / `playSlideIn()` と同じ動きを、スマホと PC ウインドウの両方に入れる。
  スマホと PC ウインドウで同じ部品（例: `web/v4/deck/swipe-motion.js`）を使い、判定も1か所にまとめる（今はスマホの `swipe.js` と `pc-pointer.js` で判定の数字が違う）。
- 動かすのは盤面だけで、上の帯（ページ名・前後のボタン）は動かさない。
- 端末の「視差効果を減らす」（`prefers-reduced-motion: reduce`）のときは動かさずに切り替える。
- UI テスト: スワイプの途中で盤面の `transform` が指の動きに合わせて変わる、離すとページが変わる、短いと元に戻る（スマホと PC ウインドウ）。

## 3. スワイプできない部品を書いておく

- 設定のカタログの説明に、フェーダー（スピーカー・マイク）、ホイール（縦・回転）、タッチパッド、テンキーの4種類だけ、
  「この上ではページのスワイプは効きません」（英: "Swiping between pages does not work on this part."）を足す。今の説明（「指で上下して調整」など）の後ろに続ける。
- スマホのメニューの「左右のスワイプで前後のページへ移動します」（`menu.swipeNote`）を、
  「左右のスワイプで前後のページへ移動します（フェーダー・ホイール・タッチパッド・テンキーの上を除く）」にする
  （英: "Swipe left or right to move between pages (except on faders, wheels, the touchpad and the keypad)"）。
- 幅 1100px の設定画面と、幅 320px のスマホのメニューで、日本語・英語とも文字が切れないこと。
