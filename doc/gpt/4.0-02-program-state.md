# 依頼書 4.0-02：Program の共有状態をクラスに分ける

TaPoard 4.0 作り直しの段階1（後半）です。01 に続いて **動きは 3.1 とまったく同じ**のまま、Program にばらばらに置かれている状態（ページの元に戻す、同期の番号、設定ファイルの読み書き）を、それぞれ専用のクラスに移します。01 で足りなかったテストもここで足します。

## 0. 作業の始め方

1. `develop/4.0` を最新にする（01 がマージ済みで、先頭は `15e6d12`）。
2. `develop/4.0` から `gpt/4.0-02-program-state` を切って作業する。
3. 終わったらこのブランチのまま止める（マージと push はレビュー後に Claude が行う）。

## 1. 必ず守ること（01 と同じ）

- **C# 5 で書く**（`$"..."`、`?.`、`nameof`、`=>` メソッド、自動プロパティの初期値、`using static`、`when` は使わない）。ビルドは `v4.0.30319\csc.exe`。
- **外部パッケージを入れない。新しい .cs は `src\` 直下に置く**（サブフォルダーはビルドされない）。
- **動き・API・JSON・設定ファイルを変えない。web\ は触らない。** 返す JSON の `revision` などの値も今と同じにする。
- **テストがリフレクションで使う名前を残す**：Program のフィールド `config`、`admin`、`lan`、メソッド `Handle`、`SplitOrientationApps`、`ValidateEntry`、`Launch`、`UseHost`。
- **ロックのしかたを変えない。** 今は `Program.Gate` 1つで全体を守っていて、`/api/sync` の待ち合わせも `Monitor.Wait(Gate)` / `Monitor.PulseAll(Gate)` です。新しいクラスは自分でロックを持たず、**呼ぶ側が Gate を持っている前提**で作る（クラスのコメントにそう書く）。待ち合わせだけは Gate を受け取って使う。
- **個人情報を入れない。** 作者は `TaPoard Developer <353783363+Mimi1011-hub@users.noreply.github.com>`。
- 1つのまとまりごとに小さく commit する（英語1行）。

## 2. やること

### 2.1 ページの「元に戻す」を `PageUndo` に移す（`src\PageUndo.cs`）

今は `src\Program.Api.cs` に `pageUndoSettings`、`pageUndoAfter`、`pageUndoOrientation`、`pageUndoPage` の4つの static フィールドと `UndoSignature` があり、ページ削除・バックアップから戻す・プリセット適用・アイコンスタイル適用の4か所で同じ4行を書いています。これを1つのクラスにまとめます。

```csharp
// 呼ぶ側が Program.Gate を持っていること。
sealed class PageUndo
{
    // 変更前の設定（JSON）と、変更後の設定を覚える。orientation と page は戻したあとに表示するページ。
    internal void Remember(string beforeJson, Settings after, string orientation, int page);
    // 覚えた後に設定が変わっていなければ true と戻す設定を返す。戻したら中身は消える。
    internal bool TryTake(Settings current, out Settings restored, out string orientation, out int page);
    internal void Clear();
    // 今の UndoSignature をここへ移す（devices を除いて比べる）。
    internal static string Signature(Settings s);
}
```

- Program に `static readonly PageUndo pageUndo = new PageUndo();` を置き、4か所の代入を `pageUndo.Remember(...)` に、`UndoDeletePage` を `TryTake` に置き換える。
- `TryTake` が false のときのエラーメッセージ（「その後に設定が変わったため、元に戻せません。」）は今と同じにする。
- 戻すときに token・pairingKey・devices を今の設定から引き継ぐ処理は、今と同じ場所（UndoDeletePage）に残してよい。

### 2.2 同期の番号と待ち合わせを `SyncHub` に移す（`src\SyncHub.cs`）

今は Program に `revision`、`phoneLastSeen`、`Signal()`、`TouchPhone()`、`PhoneConnected()` があり、`WaitForSync` が `Monitor.Wait(Gate, 15000)` しています。

```csharp
// 呼ぶ側が gate（Program.Gate）を持っていること。
sealed class SyncHub
{
    internal SyncHub(object gate);
    internal long Revision { get; }               // 今の revision
    internal void Signal();                       // revision++ と Monitor.PulseAll(gate)
    internal bool Wait(long known, int timeoutMs); // known == Revision のときだけ Monitor.Wait(gate, timeoutMs)
    internal void Touch(bool localRequest);       // 今の TouchPhone と同じ
    internal void MarkPhoneSeen();                // WaitForSync の phoneLastSeen = UtcNow
    internal bool PhoneConnected { get; }         // 30 秒以内
}
```

- Program に `static readonly SyncHub sync = new SyncHub(Gate);` を置く（`Gate` より後ろで宣言する。static の初期化は書いた順なので、前に置くと null が渡る）。
- Program の `Signal()`、`TouchPhone()`、`PhoneConnected()` は、中身を `sync.…` を呼ぶだけの1行にして残してよい（呼び出し元が多いので、名前は残して中身だけ移す）。
- JSON で返している `revision = revision` は `revision = sync.Revision` にする。`revision` と `phoneLastSeen` の static フィールドは消す。

### 2.3 設定ファイルの読み書きを `ISettingsStore` に移す（`src\SettingsStore.cs`）

```csharp
interface ISettingsStore
{
    Settings Load(/* 今の SettingsFile.Load に渡している引数 */);
    void Save(Settings settings);
    object ListBackups();                  // 今の SettingsBackups.List(Data) と同じ戻り値
    Settings ReadBackup(string id);        // 今の SettingsBackups.Read(Data, id)
}
sealed class FileSettingsStore : ISettingsStore { /* data フォルダーを受け取り、SettingsFile / SettingsBackups を呼ぶだけ */ }
```

- Program に `static ISettingsStore store = new FileSettingsStore(Data);` を置く（`Data` より後ろで宣言する）。テスト用に `internal static void UseStore(ISettingsStore value)` も置く。
- `Save()`、起動時の `SettingsFile.Load(...)`、`/api/backups` と `/api/backups/restore` の呼び出しを `store` 経由にする。
- `config` フィールドは **Program に残す**（テストが使っているため。設定を持つ場所を変えるのは後の依頼書）。
- 自動バックアップを作るタイミング（2分に1回まで・30件）は今のまま。SettingsFile / SettingsBackups の中身は書き換えない。

### 2.4 テストしやすいように2つ取り出す（01 の残り）

HTTP の応答を書く部分と切り離すため、次の2つを Program の中で別メソッドに取り出す。中身は今のコードをそのまま移す。

- `static byte VolumeKey(string action)`：`RunAction` の up / down / mute → 0xAF / 0xAE / 0xAD。`RunAction` はこれを使って `host.Pointer.KeyTap(...)` する。
- `static AudioState ApplyAudio(Dictionary<string, object> input, out string target, out bool notify)`：`SetAudio` の前半（volume / delta / toggleMute の判定と host.Audio の呼び出し、どれもなければ同じ例外）。`SetAudio` はこれを呼んでから、今と同じように Gate の中で Signal と応答をする。

### 2.5 テストを足す

`tests\run-unit.ps1` に足す（必要なら `tests\Fakes.cs` も一緒にコンパイル）。

- `tests\PageUndoTests.cs`：
  - Remember → 何も変えずに TryTake → true で、覚えた前の設定が返る
  - Remember → 設定のボタンを1つ変える → TryTake → false
  - Remember → devices だけ変える → TryTake → true（端末の追加では戻せなくならない）
  - TryTake のあと、もう一度 TryTake → false
- `tests\SyncHubTests.cs`：
  - Signal で Revision が1増える
  - Wait(known ≠ Revision) はすぐ戻る、Wait(known == Revision, 50) は約 50ms 待って戻る、別スレッドの Signal で待ちが解ける（どれも lock(gate) の中で呼ぶ）
  - Touch(false) を初めて呼ぶと Signal され、PhoneConnected が true になる。Touch(true) では変わらない
- `tests\HostTests.cs` に追加：
  - VolumeKey("up"/"down"/"mute") が 0xAF / 0xAE / 0xAD
  - ApplyAudio に volume / delta / toggleMute を渡すと、それぞれ偽物の SetVolume / AdjustVolume / ToggleMute が呼ばれ、notify が今の決まりどおり（volume は final が true のときだけ true）
  - スタートメニューのアプリ（`shell:AppsFolder\…`）の Launch で `StartApp` が呼ばれ、`StartProcess` は呼ばれない
- 偽物の `ISettingsStore`（メモリに持つだけ）を `tests\Fakes.cs` に足し、少なくとも1つのテストで `Program.UseStore` を使って、実際のファイルを書かないことを確かめる。
