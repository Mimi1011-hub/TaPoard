## 3. やること

### A（チャット1）「接続」

#### 3.1 C#：接続用の URL を返す API を1つ足す

今は QR 用の URL が古い `GET /api/settings` にしかなく、これは 16 で消します。代わりを作ります。

- `PairingController.cs` に `GET /api/v3/connect`（`ApiAccess.Admin`）を足す。返すもの：

```json
{ "iphoneUrl": "http://<PC名>:<port>/#connect=<token>", "androidUrl": "http://<IP>:<port>/#connect=<token>", "urls": ["http://<IP>:<port>/"] }
```

- 作り方は `DeckController.GetSettings` の `lanUrl`・`ipUrls`・`androidUrl`・`fragment` と同じ（`state.Gate` の中で読む）。同じ式を2か所に書かず、小さな内部クラス（例：`ConnectLinks`）に出して両方から使う。
- `tests\ApiRouteTableTests.cs` の表に1行足す（48 → 49）。URL の組み立てには小さなテストを足す（IP が無いときは `androidUrl` が PC 名の URL になること、トークンが `Uri.EscapeDataString` されること）。
- C# 5 の書き方だけ（`00` の決まりどおり）。

#### 3.2 「接続」の欄

手本：`app.js` の `drawPairQr`（6514 行〜）、`pairFetch`（7388〜）、`refreshPairing`・`renderPairing`（7448〜7516）、端末を全部切る処理（6754 行あたり）、`firewallText`・`refreshFirewall`・`waitForRepair`（7909〜7990）。

新しいファイル（目安）：`settings\connect.js`（欄の組み立て）、`settings\connect-qr.js`（QR）、`settings\pairing-list.js`（端末）、`settings\firewall.js`。

- **QR**：`GET /api/v3/connect` の URL を QR にする。「iPhone」「Android」の切り替え（最初は iPhone）。下に URL を文字でも出す（トークンの部分は出さず、`#` より前だけ）。`qrcode.js` は `settings.html` に `<script>` で読み込む（これだけは同梱ライブラリの名前を使ってよい）。
- **つなぎたい端末（承認待ち）**：`GET /api/pair/manage` の `pending`。端末名・アドレス・確認コードを出し、「許可」と「拒否」（`POST /api/pair/manage` `{id, code, approve:true}` または `{id, code, approve:false}`。`code` は `pending` で来たものをそのまま送る）。
- **つないだ端末**：`devices`。名前と登録日、「解除」（`{id, revoke:true}`）。解除は確認を1回出す（設定ウインドウの中の確認。`window.confirm` は使わない。12 の `look-dialog.js` と同じ作りの小さな確認を `settings\confirm-dialog.js` として作り、ここと 3.2 の「全部切る」で使う）。
- **全部の端末を切る**：`POST /api/rotate`。確認のあと実行し、QR を作り直す。
- **更新**：この欄を開いている間だけ 2 秒ごとに `GET /api/pair/manage` を読む。ほかの欄に移ったら止める。返り値の `revision` が同じなら描き直さない。
- **ファイアウォール**：`GET /api/firewall` の状態を1行で出し、直せるときは「直す」（`POST /api/firewall/repair`、手本と同じ待ち方）。文言は手本の `firewallText` をキーにして移す。
- 失敗はお知らせ（`showNotice`）に出す。401・403 は「トレイから設定を開き直してください」。

### B（チャット2）「PC画面」と「全般」

#### 3.3 「PC画面」の欄

手本：`web\pc-window.js`（74 行）と `web\pc-window.html` の選択肢。

- `GET /api/pc-window` → `{options, open, viewOnly, runtimeAvailable}`。項目：`startup`・`startTopmost`・`buttonSize`・`aspect`（選択）、`opacity`（スライダー、% 表示）、`autoHideBar`・`showInfo`・`confirmClose`（チェック）。選択肢の値と文言は `pc-window.html` と同じ。
- 変えたらすぐ `POST /api/pc-window`（全部の項目を送る）。続けて変えたときは順番に送る（手本の `saving` の鎖と同じ）。返り値で表示を直す。
- 「PC 用ウィンドウを開く／前に出す」「全画面で開く」（`POST /api/pc-window/open` `{fullscreen}`）。`runtimeAvailable` が `false` なら説明を出してボタンを押せなくする。
- 新しいファイル：`settings\pc-window-settings.js`。

#### 3.4 「全般」の欄

- **画面を消さない**：`deck.keepAwake`。`EditorState` に小さな関数を足して `change()` を通す（元に戻す・自動保存の対象）。
- **天気の場所**：今の場所は `GET /api/v3/state` の `weather.location`。検索は `POST /api/weather/search` `{query}` → `results`、選んだら `POST /api/weather/location` `{name, latitude, longitude, timezone}`。手本は `renderWeatherLocation`（6593〜6657）。候補の文字は `textContent`。
- **このアプリについて**：バージョン（`GET /api/v3/state` の `appVersion`）と PC 名（`computer`）。
- 新しいファイル：`settings\general.js`、`settings\weather-place.js`。
- **「次の更新で使えるようになります」をなくす**：3つの欄がそろうので、`Sections` の `onUnavailable` と `settings.comingSoon` のキーを消す（詳しい設定のボタンは C で直すので、B の間は残してよい）。

### C（チャット3）アプリの追加と詳しい設定

#### 3.5 アプリの追加

手本：`startImport`・`pollImport`（6661〜6740）。

- 「配置」の一覧の上に「アプリや URL を追加」ボタン。`POST /api/import` `{}` → `{id}`（PC に追加用のウインドウが開く）。そのあと 1 秒ごとに `GET /api/import` を読み、`id` が違えば「ほかの所で始まりました」で止める。`result` が来たら終わり。
- `result.cancelled` ならお知らせだけ。`result.apps` は、今プレビューで見ている向き・ページの空きマスに順に置く（`EditorState.firstSpace` と `addItem`）。
  - 同じ向きにもう同じもの（`url` が同じ、または `path` が大文字小文字を無視して同じ）があれば飛ばす。
  - 全部で **元に戻す1回分**にする（`change()` を1回）。
  - 置けた数・飛ばした数・空きが無くて置けなかった数をお知らせに出す。
- 待っている間はボタンを押せなくし、「開いたウインドウにアイコンを落とすか、URL を入れてください」と出す。設定ウインドウを閉じたら待つのをやめる。
- 新しいファイル：`settings\app-import.js`。

#### 3.6 種類ごとの詳しい設定

今は右の設定の「詳しい設定」ボタンが「次の更新で…」を出すだけです。これを本物にします。

- **出し方**：ボタンで別の画面を開くのではなく、右の設定の共通項目の下に、その種類の項目をそのまま並べる（ボタンは消す）。`inspector.js` は 130 行あるので、種類ごとの中身は `settings\details\` に分ける。`inspector.js` からは `detailsFor(item)` のような1つの入口だけを呼ぶ。
- 値は `EditorState.updateItem(address, { options: {...} })`（`options` は今の値に重ねて全部を渡す）。ショートカットキーは `hotkey`、音の機器は `deviceId`・`deviceTarget`・`deviceName`。
- 種類と項目（文言・選択肢・初期値は手本と同じ。「設定を保存」という言葉は自動保存なので消す）：

| 種類 | 手本（`app.js`） | 項目 |
|---|---|---|
| 時計 `clock` | `buildClockSettings` 5780〜 | `options.style`、秒・日付・曜日・12時間表示 |
| PC情報 `metrics` | `buildMetricsSettings` 5815〜 | `options.primary`、`options.cycle`、`options.gpuId`・`options.gpuName`（GPU の一覧は手本と同じ取り方） |
| ホイール `wheel` | `buildWheelSettings` 5899〜 | `options.style`、`options.sensitivity`、`options.multiplier`、反転、中クリック、Ctrl・Shift・Alt |
| スライドショー `slideshow` | `buildSlideshowSettings` 5973〜 | `options.folder`（「フォルダを選ぶ」＝`POST /api/slideshow/pick-folder` `{folder}` → `{folder, picked, count}`）、`options.interval`、順番、表示のしかた |
| タッチパッド `touchpad` | `buildTouchpadSettings` 6054〜 | `options.speed`、加速、タップでクリック、2本指スクロール、反転、`options.longPress` |
| ショートカット `hotkey` | `buildHotkey` 7254〜 | キーを押して登録、一覧から選ぶ、「標準に戻す」 |
| 音の機器 `audioDevice` | `buildDeviceSelector` 557〜、`fillDeviceSelector` 593〜 | `GET /api/devices` の一覧から選ぶ |
| 天気 `weather` | なし | 「場所は『全般』で決めます」と、全般の欄を開くボタンだけ |

- 手本にある項目は名前を上の表に書いていなくても全部移す。手本に設定が無い種類（テンキーなど）は何も出さない。
- キーの登録中は、設定ウインドウのショートカット（Ctrl+Z など）が動かないようにする。
- ファイルは種類ごとに1つ（例：`details\clock-details.js`）。共通の入力部品（チェック・選択・スライダー）は `details\fields.js` に1回だけ書く。
